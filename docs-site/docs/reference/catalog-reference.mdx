Ante loads its built-in presets and merges [`~/.ante/catalog.json`](#catalogjson-schema) at startup. Restart Ante after editing the file.

## Find a provider {#built-in-providers}

Open `/providers` to see which providers are connected. From the shell, run `ante catalog` to print the merged catalog as JSON. To list provider IDs and their configured credential references, use:

```bash
ante catalog | jq '.providers[] | {id, credential}'
```

An `env:` reference names an environment variable. For sign-in and API-key setup, see [Connect a provider](/usage/providers).

## Find a model {#models-by-provider}

Open `/models` to see the current provider’s presets. To list Antix presets from your installation:

```bash
ante catalog | jq -r '.providers[] | select(.id == "antix") | .preferred_models[]?.id'
```

A provider can serve a model before it appears in your installed presets. Pass its model ID directly with `ante --provider <provider> --model <model_id>`. See [Choosing a model](/usage/models-and-thinking#selecting-a-model).

## Custom catalog

Create `~/.ante/catalog.json` to add a provider Ante doesn't ship, patch a built-in one, or tweak a model's defaults. It is merged on top of the built-in presets at startup, so you only specify what you want to add or change. Prefer not to write it by hand? Run `/add-provider` in the TUI: Ante discovers the endpoint's models, can probe which effort levels each one accepts, and writes the entry for you (restart to load it). The examples below are the common cases; see the [schema below](#catalogjson-schema) for all fields and [Credentials](#credentials) for every way to authenticate.

### Add a hosted provider

Most hosted endpoints are OpenAI-compatible. Register one with `wire_style: "OpenAiCompatible"`, point `base_url` at it, and list the models you want to appear in the picker:

```json
{
  "providers": {
    "together": {
      "display_name": "Together AI",
      "base_url": "https://api.together.xyz/v1",
      "wire_style": "OpenAiCompatible",
      "credential": "env:TOGETHER_API_KEY",
      "preferred_models": [
        {
          "id": "moonshotai/Kimi-K2-Instruct",
          "description": "Kimi K2 on Together",
          "max_tokens": 16384,
          "context_limit": 128000,
          "effort": "medium"
        }
      ]
    }
  }
}
```

```bash
export TOGETHER_API_KEY="..."
ante --provider together --model moonshotai/Kimi-K2-Instruct
```

To keep the key out of your shell profile instead, leave `credential` out and store the key once with `ante auth add together`. A new provider with no `credential` reads the key stored under its own name.

### Add Tsubasa

[Tsubasa](https://tsubasa.sh) uses the existing `OpenAiCompatible` transport. Merge this entry into `~/.ante/catalog.json` and set `TSUBASA_API_KEY` in your environment:

```json
{
  "providers": {
    "tsubasa": {
      "display_name": "Tsubasa",
      "base_url": "https://api.tsubasa.sh/v1",
      "wire_style": "OpenAiCompatible",
      "credential": "env:TSUBASA_API_KEY",
      "preferred_models": [
        {
          "id": "tsubasa-fast",
          "context_limit": 32768,
          "max_tokens": 512,
          "supported_efforts": [],
          "support_vision": false
        },
        {
          "id": "tsubasa-pro",
          "context_limit": 32768,
          "max_tokens": 512,
          "supported_efforts": [],
          "support_vision": false
        }
      ]
    }
  }
}
```

Start with a small project and a bounded prompt:

```bash
ante --provider tsubasa --model tsubasa-fast --short-prompt \
  --no-skills --disable-auto-memory --permission-mode strict
```

Use `tsubasa-pro` to select the other alias. These are text-only profiles with no reasoning-effort parameter. The 32,768-token context includes the system prompt, tool definitions, conversation, and reserved output; the 512-token output setting is a conservative starting point. Additional instructions, MCP tools, file content, or history can exceed that budget. Tool use also requires the selected model's current tool capability; check the provider's model listing before an agent session.

### Declare the effort levels a model accepts

Set `supported_efforts` on a model when your endpoint accepts different levels from the built-in defaults. Ante uses the levels its API can express for both the [effort slider](/usage/models-and-thinking#effort) and outgoing requests. This model accepts three levels and defaults to `high`.

```json
"preferred_models": [
  {
    "id": "kimi-k3",
    "effort": "high",
    "supported_efforts": ["low", "medium", "high"]
  }
]
```

A request below the supported range uses the lowest level. Between two supported levels, Ante uses the lower one. For a model that accepts `min`, Responses sends `none` and Gemini sends `MINIMAL`.

An empty list (`"supported_efforts": []`) declares that the model takes no effort setting at all. There is no API that reports supported levels, so when in doubt let `/add-provider` probe the endpoint for you.

### Add a local provider with no auth

Set `credential` to `null` for a provider that needs no key, and leave `preferred_models` off when the provider has no stable picker/default model list — handy for a local server like Ollama where the available models change as you pull them. You can still pass any model id explicitly with `--provider` and `--model`:

```json
{
  "providers": {
    "ollama": {
      "display_name": "Ollama",
      "base_url": "http://localhost:11434/v1",
      "wire_style": "OpenAiCompatible",
      "credential": null
    }
  }
}
```

```bash
ante --provider ollama --model qwen2.5-coder:7b
```

### Patch a built-in provider

When the key matches a built-in provider, only the fields you set are changed.
`"credential": null` stops the provider sending a credential, which suits a
local proxy:

```json
{
  "providers": {
    "openai": {
      "base_url": "http://localhost:8080/v1",
      "credential": null
    }
  }
}
```

### Disable search on a DeepSeek gateway {#deepseek}

The built-in `deepseek` provider uses the session credential to POST to `/v1/tools/search` on the same base URL. If your gateway forwards only chat requests, merge this into `~/.ante/catalog.json` and restart Ante.

```json
{
  "providers": {
    "deepseek": { "supports_web_search": false }
  }
}
```

### Send a session header

For a gateway that groups requests by conversation, put `${session_id}` in a `headers` value or an `extra_body` string. This example patches the built-in OpenAI provider; use your gateway provider's key when configuring one:

```json
{
  "providers": {
    "openai": {
      "headers": { "X-Session-ID": "${session_id}" },
      "extra_body": { "prompt_cache_key": "ante-${session_id}" }
    }
  }
}
```

Ante fills in the conversation's ID for each session. Resuming keeps that ID, while a fork uses its own new ID. Subagent requests carry the parent's ID so the gateway can group delegated work with the parent. See [Templates](#templates) for environment variables in the same places.

### Send extra request parameters

Gateways and proxies often require a parameter Ante doesn't model. Put it in `extra_body` and it is merged into every chat and streaming request body for that provider:

```json
{
  "providers": {
    "my-gateway": {
      "display_name": "My Gateway",
      "base_url": "https://gateway.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "credential": "env:MY_GATEWAY_API_KEY",
      "extra_body": {
        "service_tier": "priority"
      }
    }
  }
}
```

`extra_body` can only add fields — keys Ante already generates for that wire style (`model`, `messages`, `stream`, and friends) are dropped at startup with a notice, and the provider still loads. See [Extra request fields](/reference/catalog-reference#extra-request-fields) for the full reserved list.

### Override model defaults

Patch a model on the provider that lists it. A `preferred_models` entry whose `id` matches a built-in model changes only the fields you set; everything else is left alone:

```json
{
  "providers": {
    "anthropic": {
      "preferred_models": [
        { "id": "claude-opus-5-5", "effort": "max" },
        { "id": "claude-sonnet-5-5", "effort": "high", "max_tokens": 64000 }
      ]
    },
    "openai": {
      "preferred_models": [{ "id": "gpt-6-luna", "effort": "min", "temperature": 0.2 }]
    }
  }
}
```

A model served by several providers is patched on each one you use.

## Third-party providers

### Using Open Router

1. Sign up at [openrouter.ai](https://openrouter.ai/) and generate an API key.
2. Set your API key:
   ```bash
   export OPENROUTER_API_KEY="sk-or-..."
   ```
3. Use any model from [Open Router's model list](https://openrouter.ai/models):
   ```bash
   ante --provider openrouter --model deepseek/deepseek-v4.1-flash-1017
   ```

### OpenAI transports

The `openai` and `openai-subscription` providers can stream responses two ways:

| Transport | Endpoint | Default |
|---|---|---|
| `http_sse` (HTTP + SSE) | `https://api.openai.com/v1/responses` (or the subscription equivalent) | ✅ |
| `websocket_auto` (persistent WebSocket) | `wss://.../v1/responses` | opt-in |

WebSocket mode keeps one connection open per session and continues each turn with `previous_response_id` plus only the new input items. In long agentic tool loops this eliminates per-turn round-trip latency. See OpenAI's [WebSocket mode guide](https://developers.openai.com/api/docs/guides/websocket-mode) for the underlying protocol.

Opt in via the process-scoped env var (default is `http_sse`):

```bash
ANTE_OPENAI_TRANSPORT=websocket_auto ante --provider openai --model gpt-6-luna
```

Accepted values: `http_sse`, `websocket_auto`. Unknown values warn and fall back to `http_sse`.

Notes:

- All model-generation calls use the streaming transport, including TUI turns, headless tasks, compaction, goal judging, and ambient hints. Calls that need a complete response collect that stream, so they can also use WebSocket when enabled. Cancelling a WebSocket call discards its connection so the next request cannot read the abandoned response.
- Eligible WebSocket failures fall back to HTTP/SSE within the remaining call budget; falling back does not reset the deadline. If the budget expires, the call reports a timeout. Auth failures (`401`/`403`) disable WebSocket for the rest of the session.
- Works against both `api.openai.com` (API-key) and the ChatGPT subscription backend at `chatgpt.com/backend-api/codex`.
- To verify which transport is active: in debug builds, toggle the debug panel (`Ctrl+L`) and check the **Info** tab for the `OpenAI Transport:` line. Otherwise grep your session log for `transport selected`:

  ```bash
  grep "transport selected" ~/.ante/logs/*/ante.*.log
  ```

### OpenAI-compatible providers

Many LLM providers expose an OpenAI-compatible API (e.g., Together AI, Fireworks, Groq Cloud, Perplexity). For a one-off you can reuse the built-in `openai-compatible` provider via env vars (no catalog edit needed):

1. Set the base URL — the per-provider variable takes precedence over `MODEL_BASE_URL`:
   ```bash
   export OPENAI_COMPATIBLE_BASE_URL="https://api.together.xyz/v1"
   ```
2. Set your API key:
   ```bash
   export OPENAI_COMPATIBLE_API_KEY="your-provider-api-key"
   ```
3. Run with the OpenAI Compatible provider:
   ```bash
   ante --provider openai-compatible --model meta-llama/Llama-3-70b-chat-hf
   ```

For something you'll use repeatedly, add a named provider to your [custom catalog](#custom-catalog) instead so it shows up in the picker.

## `catalog.json` schema

`~/.ante/catalog.json` is merged on top of the built-in presets at startup. It has three optional top-level keys, each a map keyed by name:

```json
{
  "providers":      { /* add or patch providers */ },
  "oauth_profiles": { /* OAuth sign-ins; see Credentials */ },
  "helpers":        { /* credential commands; see Credentials */ }
}
```

A `providers` entry whose key matches a built-in (e.g. `openai`) patches that preset field by field; a new key adds a provider. The map key is the value you pass to `--provider`. An `id` (or legacy `name`) field inside an entry is ignored.

:::note
`~/.ante` can be relocated with the `ANTE_HOME` environment variable; the catalog is always `$ANTE_HOME/catalog.json`.
:::

### Provider fields

| Field | Required | Description |
|---|---|---|
| `display_name` | New providers: optional | Friendly name shown in the TUI. New providers default to the provider map key when omitted. |
| `base_url` | New providers: ✅ | API base URL. |
| `wire_style` | New providers: ✅ | API dialect Ante speaks — `AnthropicMessage`, `OpenAiCompatible`, `OpenAiResponse`, or `Gemini`. |
| `credential` | — | The credential to send: a reference such as `env:MY_KEY`, a list of them, or `null` for none (see [Credentials](#credentials)). A new provider that omits it reads `secret:<its key>`. |
| `credential_header` | — | The header the credential goes in, sent as is. Omitted, it is sent as `Authorization: Bearer <credential>`. |
| `headers` | — | Extra headers sent with every request, as a string→string map. Values take [templates](#templates). `null` on a key removes a built-in's header. The credential never goes here. |
| `extra_body` | — | Provider-specific JSON fields merged into every chat and streaming request body (see [Extra request fields](#extra-request-fields)). String values take [templates](#templates). |
| `thinking_display` | — | Readable reasoning output: `off`, `concise`, or `detailed`, independent of reasoning effort (see [Thinking display](#thinking-display)). |
| `max_request_images` | — | Non-negative integer limiting images per request across all models on this provider. Keeps the newest images and replaces older ones with text markers; `0` omits all images, `null` clears the cap. See [Request image limits](#request-image-limits). Available since v0.3.2. |
| `supports_web_search` | When `true`, sessions offer `WebSearch` by default. The endpoint must support the corresponding search request. Defaults to `false` for new providers. For a chat-only gateway, see [DeepSeek](#deepseek). |
| `preferred_models` | — | Models shown for this provider in the picker and used as provider defaults (see [Model fields](#model-fields)). For built-in provider overlays, matching model ids are patched and new ids are appended; omitted leaves the preset list unchanged. |
| `stream_idle_timeout_secs` | — | Timeout in seconds; defaults to `300`. Opening a stream uses one shared budget for response headers, error bodies, OAuth refresh, transport retries and backoff, and WebSocket-to-HTTP fallback. Buffered HTTP calls also read their body within that budget. Once streaming, the same duration limits consecutive transport silence; every read resets it, including keepalives, lifecycle events, and partial tool arguments. All model-generation calls stream, including compaction, goal judging, and ambient hints. Raise it for slow local or proxied endpoints; lower it to detect stalls sooner. |

```json
{
  "providers": {
    "my-provider": {
      "display_name": "My Provider",
      "base_url": "https://api.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "credential": "env:MY_PROVIDER_API_KEY",
      "headers": { "X-Org": "my-team" },
      "preferred_models": [
        {
          "id": "my-model",
          "description": "My fine-tuned model",
          "max_tokens": 32000,
          "context_limit": 200000,
          "effort": "medium",
          "supported_efforts": ["low", "medium", "high"]
        }
      ]
    }
  }
}
```

For built-in providers, include only the fields you want to change. A
`credential` you set replaces the preset's list whole. To repoint Anthropic
at a local proxy that takes no key and drop its built-in beta header:

```json
{
  "providers": {
    "anthropic": {
      "base_url": "http://localhost:8080/v1",
      "credential": null,
      "headers": { "anthropic-beta": null }
    }
  }
}
```

### Thinking display

`thinking_display` controls readable reasoning output independently of [effort](/usage/models-and-thinking#effort). Accepted values are `off`, `concise`, and `detailed`. Built-in hosted-provider presets default to `detailed`; omitting the field in an overlay keeps that preset, while `null` clears it and leaves display behavior to the endpoint. A new custom provider sends no display parameter until you set one.

```json
{
  "providers": {
    "openai": { "thinking_display": "concise" },
    "anthropic": { "thinking_display": "off" }
  }
}
```

The setting never changes reasoning effort or continuation state. OpenAI Responses maps the three modes to no summary, concise summary, or detailed summary. Anthropic maps `off` to omitted reasoning and both readable modes to its summarized form; Gemini enables thought summaries for `concise` and `detailed`. Generic OpenAI-compatible Chat Completions has no standard display control and ignores the field; provider-specific controls can still go in `extra_body`.

### Request image limits

Use `max_request_images` when an endpoint limits how many images it accepts in one request. The cap applies to all models on that provider and counts images across the entire request, including user messages and tool results. Document attachments, such as PDFs, do not count.

```json
{
  "providers": {
    "openrouter": { "max_request_images": 8 }
  }
}
```

Ante retains the newest images in request order and replaces older ones with text explaining that they were omitted to fit the provider's image limit. It applies this just before sending the request on all four wire styles; the saved conversation keeps its images. Set `0` to send no images. Built-in presets are uncapped; omitting the field preserves the provider's existing setting, and `null` clears it. Restart Ante after editing the catalog.

Once the cap is reached, each new image can replace an image in an earlier message in the outgoing request. That changes the prompt prefix and can reduce cache reuse from that point onward.

### Extra request fields

Some gateways and proxies require parameters Ante doesn't model — a service tier, a routing hint, a vendor-specific beta block. `extra_body` is a JSON object merged into the top level of every chat and streaming request body Ante sends to that provider:

```json
{
  "providers": {
    "my-gateway": {
      "base_url": "https://gateway.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "credential": "env:MY_GATEWAY_API_KEY",
      "extra_body": {
        "service_tier": "priority",
        "routing": { "region": "us-east" }
      }
    }
  }
}
```

Values are passed through verbatim, so any JSON shape works. On a built-in provider overlay, `extra_body` merges key by key into the preset's — matching keys are replaced, others are left alone.

`extra_body` can only add fields, never override the ones Ante generates for the selected `wire_style`:

| `wire_style` | Reserved keys |
|---|---|
| `AnthropicMessage` | `model`, `max_tokens`, `messages`, `system`, `temperature`, `tools`, `stream`, `thinking`, `stop_sequences`, `output_config`, `cache_control` |
| `OpenAiCompatible` | `model`, `messages`, `reasoning_effort`, `max_tokens`, `stream`, `stream_options`, `temperature`, `top_p`, `top_k`, `stop`, `tools`, `tool_choice`, `thinking`, `enable_thinking`, `thinking_budget`, `enable_search`, `search_options` |
| `OpenAiResponse` | `model`, `instructions`, `input`, `tools`, `tool_choice`, `parallel_tool_calls`, `max_output_tokens`, `temperature`, `reasoning`, `stream`, `include`, `store` |
| `Gemini` | `contents`, `systemInstruction`, `generationConfig`, `tools`, `toolConfig` |

For Claude Sonnet 5.5 on Anthropic Messages, `tool_choice` cannot require a tool call or force a specific tool. Ante reports that error before sending the request.

A reserved key is dropped at catalog load and named in the startup notice; the rest of the provider still loads. To change one of these, use the [model fields](#model-fields) or the [environment overrides](#environment-overrides) instead:

```
Skipped 1 entry in ~/.ante/catalog.json:
  - providers.my-gateway.extra_body: ignoring Ante-owned request field(s): model
```

### Credentials

A provider's `credential` says which credential it sends. It is a reference, a list of references, or `null`:

```json
{
  "providers": {
    "corp":       { "base_url": "https://llm.corp/v1", "wire_style": "OpenAiCompatible",
                    "credential": ["env:CORP_API_KEY", "secret:corp"] },
    "keyed":      { "base_url": "https://api.keyed.dev/v1", "wire_style": "OpenAiCompatible",
                    "credential": "env:KEYED_API_KEY", "credential_header": "x-api-key" },
    "local-proxy": { "base_url": "http://127.0.0.1:4000/v1", "wire_style": "OpenAiCompatible",
                     "credential": null }
  }
}
```

| Reference | Reads |
|---|---|
| `env:NAME` | The environment variable `NAME`. |
| `secret:NAME` | A key stored with `ante auth add NAME` (or added in `/providers`). |
| `oauth:PROFILE` | A sign-in made with `ante auth login PROFILE`. `PROFILE` is `anthropic`, `openai`, `antix`, or one of your [`oauth_profiles`](#oauth-profiles). |
| `helper:NAME` | The output of a command in [`helpers`](#helpers). |

- **A list** is tried in order, and the first reference that has a value is sent. In `/providers` you can pick another one for the session.
- **Omitted** on a new provider, `credential` reads `secret:<provider key>`, so `ante auth add <provider key>` is all the setup it needs.
- **`null`** sends no credential.
- **A plain key is refused.** `"credential": "sk-..."` is an error, so a key never sits in `catalog.json`. Store it with `ante auth add` and refer to it as `secret:NAME`.
- **Placement:** the credential goes out as `Authorization: Bearer <credential>`. Set `credential_header` to send it as is in another header, such as `x-api-key`.

A provider is ready when one of its references has a value. Providers that aren't ready are skipped during auto-detection; using one fails with the fix, for example "Set environment variable CORP_API_KEY or run `ante auth add corp`".

#### Second accounts

Add `/label` to sign in to a second account on the same profile, or to store a second key:

```bash
ante auth login anthropic/work
ante auth add corp/staging
```

A reference without a label, such as `oauth:anthropic`, can use any of them. A labeled one, such as `oauth:anthropic/work`, uses only that one.

#### Helpers

A helper is a command that prints a credential: a token from a vault, a cloud CLI, or a rotating key. Define it under `helpers` and reference it as `helper:NAME`:

```json
{
  "helpers": {
    "corp": { "command": ["corp-token", "--audience", "llm"], "ttl_secs": 3000 }
  },
  "providers": {
    "corp": { "base_url": "https://llm.corp/v1", "wire_style": "OpenAiCompatible",
              "credential": "helper:corp" }
  }
}
```

`command` runs as written, with no shell, and must finish within 15 seconds. The first line of its output is the credential. Ante reuses it for `ttl_secs` seconds (at most a year), and runs the command again when that time is up or when the server rejects the credential. If the command fails, the request fails with the helper's name; Ante never falls back to another credential. See [Use a command for tokens](/usage/custom-sign-ins#helpers) for worked examples.

#### OAuth profiles

An OAuth profile is the recipe for a sign-in. The built-in ones are `anthropic`, `openai`, and `antix`. Add your own under `oauth_profiles` to sign in to another service, with no code change:

```json
{
  "oauth_profiles": {
    "corp": {
      "client_id": "ante",
      "redirect_uri": "http://localhost:1455/callback",
      "authorize_url": "https://sso.corp/authorize",
      "token_url": "https://sso.corp/token",
      "scopes": ["openid", "offline_access"],
      "account_claim": ["email"]
    }
  },
  "providers": {
    "corp": { "base_url": "https://llm.corp/v1", "wire_style": "OpenAiCompatible",
              "credential": "oauth:corp" }
  }
}
```

Then run `ante auth login corp`. `client_id`, `redirect_uri`, `authorize_url`, and `token_url` are required; `redirect_uri` must be on `http://localhost` or `http://127.0.0.1`. Optional fields include `scopes`, `resource`, `authorize_params`, `token_request_encoding` (`json` or `form`), and `account_claim` (the JWT claim shown as the account in `ante auth list`). An entry named like a built-in replaces it whole. An `oauth:` reference to a profile that doesn't exist is an error. [Add an OAuth sign-in](/usage/custom-sign-ins#oauth-profile) walks through a full setup.

#### Templates

String values in a provider's `headers` and `extra_body`, and in an `oauth_profiles` entry, can use:

| Template | Becomes |
|---|---|
| `${NAME}` | The environment variable `NAME`. |
| `${NAME:-default}` | `NAME`, or `default` when it is not set. |
| `${session_id}` | The ID of the session making the request, in `headers` and `extra_body` only (see [Send a session header](#send-a-session-header)). |

Environment variables are read when the catalog loads. A `${NAME}` with no value and no default refuses the whole entry, naming the variable. Templates never carry a credential; use `credential` for that.

### Model fields

A model is described inside a provider's `preferred_models`. On a built-in provider, an entry whose `id` matches an existing model patches it, and a new `id` is added. Every field except `id` is optional:

| Field | Description |
|---|---|
| `id` | Model id (`name` is accepted as a legacy alias). |
| `display_name` | Friendly name. |
| `description` | Short description shown in the model picker. |
| `temperature` | Sampling temperature. Anthropic Messages requires `1` while thinking is active, and Claude Haiku 5.5 always requires `1`. The Responses API sends a configured temperature when reasoning is `none` or unset and omits it while reasoning is active. |
| `top_p` | Nucleus sampling cutoff. |
| `top_k` | Top-k sampling cutoff. |
| `max_tokens` | Maximum output tokens per turn. On `AnthropicMessage` providers that take an explicit thinking budget, it must exceed 1024 — the API's minimum budget — when an effort level is set. |
| `stop_sequences` | List of strings that end generation. |
| `context_limit` | Context window size, in tokens. |
| `effort` | Default [effort level](/usage/models-and-thinking#effort) — `min`, `low`, `medium`, `high`, `xhigh`, or `max`. Omit for models with no reasoning knob (Ante then sends no effort parameter and hides the effort slider). |
| `supported_efforts` | Levels the model accepts (same values as `effort`). Each API uses the declared levels it can express. An empty list disables the effort parameter. Omit the field to use the built-in levels. |
| `weight_class` | Size/cost tier — `Feather`, `Middle`, or `Heavy`. Drives automatic default and auxiliary model selection (see [Weight classes](#weight-classes)). |
| `support_vision` | Whether the model accepts image input. Built-in models declare this explicitly; custom models default to `true` when unspecified, and an overlay that omits it keeps the preset value. Set `false` for a text-only endpoint. Images are filtered out before sending to non-vision models without altering saved history; reading an image returns its metadata instead of pixels. |

### Weight classes

Every built-in model carries a `weight_class` — `Feather` (small/fast/cheap), `Middle`, or `Heavy` (largest/most capable). Ante uses it to pick models without you naming one:

- **Default model** — selecting a provider with no explicit model resolves to its **heaviest** model.
- **Ambient UI calls** — cosmetic thinking phrases and next-prompt suggestions use the provider's **lightest** model when it is classified as Feather or Middle. WebFetch returns page content directly to the active session model and does not use this path.

Models with no `weight_class` set fall back to catalog order. Set `weight_class` on a custom model to steer these choices.

## How a model and provider are chosen

Explicit `--provider` and `--model` flags override the `provider` and `model` values in `~/.ante/settings.json`. When neither source specifies a choice, Ante uses the auto-detection rules below.

When Ante resolves a model id it layers two sources, last wins:

1. **Provider model spec** — the selected provider's `preferred_models` entry, with your patches, if it lists that id. Otherwise, the first matching entry in catalog order. An unknown id falls back to a bare default spec.
2. **Environment overrides** — the process env vars below win over everything.

Providers are matched to models too. If you pass only `--model`, Ante picks an authenticated provider whose `preferred_models` list contains that id, falling back to an authenticated provider with no `preferred_models`, then to the default provider.

A provider you name with `--provider` or saved in settings is kept even before it is set up: Ante starts on it and says it needs setup in `/providers`. If you pass both `--provider` and `--model`, Ante uses that provider's model spec before applying environment overrides, falling back to a global lookup only when the provider does not list the id. Unknown ids are passed through as bare model specs.

When neither CLI flags nor settings name a model or provider, Ante auto-detects: it uses the first authenticated provider in catalog order (Antix comes first) and that provider's heaviest-weight model (see [Weight classes](#weight-classes)). If nothing is authenticated, it starts on Antix, ready to set up.

## Environment overrides

These process env vars override catalog values for the session without editing the file:

| Variable | Overrides |
|---|---|
| `MODEL_BASE_URL` | Base URL for all providers (a per-provider var like `ANTHROPIC_BASE_URL` takes precedence). |
| `MODEL_TEMPERATURE` | `temperature` |
| `MODEL_TOP_P` | `top_p` |
| `MODEL_MAX_TOKENS` | `max_tokens` |
| `MODEL_CONTEXT_LIMIT` | `context_limit` |

Effort has no env override — set it per run with the [`--effort` CLI flag](/reference/cli-reference#ante) or per model via the `effort` field.

Several presets also honor a dedicated base-URL env var that takes precedence over `MODEL_BASE_URL`: `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL`, `OPENAI_COMPATIBLE_BASE_URL`, `OPENROUTER_BASE_URL`, `DEEPSEEK_BASE_URL`.

## Error handling

A bad entry doesn't sink the whole file. Ante parses `catalog.json` leniently: any provider, profile, or helper entry that fails to load is skipped, and the rest still load. A setting written in a shape an earlier version used is skipped with a message naming its replacement (see [Upgrading to v0.3](/start/update#upgrading-to-v03)). Skipped entries are reported at startup and by `ante doctor`, e.g.:

```
Skipped 1 entry in ~/.ante/catalog.json:
  - providers.my-provider: missing field `base_url`
```

Only a file that isn't a JSON object at all is rejected outright. A missing `catalog.json` is fine — Ante just uses the built-in presets.
