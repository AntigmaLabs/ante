`ante-sdk` is the Rust client for Ante. Your program sends ops and receives events, while Ante runs the agent loop, tools, approvals, and providers. The SDK handles JSONL framing and the host process, so you write the harness and Ante stays the core.

The crate is published on [crates.io](https://crates.io/crates/ante-sdk) (API docs on [docs.rs](https://docs.rs/ante-sdk)), with source in [`crates/ante-sdk`](https://github.com/AntigmaLabs/ante/tree/main/crates/ante-sdk).

```bash
cargo add ante-sdk
cargo add tokio --features macros,rt-multi-thread
```

## A minimal client

This program starts a session, sends one prompt, and prints the reply as it streams. It needs `ante` on `PATH`; unset session fields fall back to the host's defaults from `~/.ante/settings.json`.

```rust
use ante_sdk::{ConnectOptions, connect, protocol::{Evt, Op, SessionRequest}};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut client = connect("stdio".parse()?, ConnectOptions::default()).await?;

    client.send(Op::StartSession(SessionRequest {
        unattended: Some(true),
        ..Default::default()
    })).await?;
    client.send(Op::UserInput("explain what this project does".into())).await?;

    while let Some(msg) = client.next_event().await {
        match msg.event {
            Evt::MessageDelta(text) => print!("{text}"),
            Evt::TurnEnd { .. } | Evt::Error(_) => break,
            _ => {}
        }
    }
    client.close().await;
    Ok(())
}
```

`unattended: true` denies calls that would need approval, which suits a program with no UI. An interactive client instead answers `TurnPause` events with `ApprovalResponse` or `QuestionResponse`.

`Client::send` returns the `Id` stamped on the op. Every event that answers it carries that `Id` as its `parent`. `client.close()` sends `Shutdown` and waits for the host to say goodbye.

## Connecting to a host

`connect` takes an `Endpoint`, which names where a host is reachable. Which session a connection drives is decided by the ops sent over it (`StartSession`, `ResumeSession`).

| Endpoint | What the client does | Host lifetime |
|---|---|---|
| `stdio` | Spawns [`ante serve --stdio`](/usage/serve) as its own child | Ends with the connection |
| `unix:<path>` | Dials the socket of an `ante serve --sock` host | Outlives the connection |
| `ws://<addr>`, `wss://<addr>` | Dials an `ante serve --ws` host, sending `ConnectOptions::token` as the bearer token | Outlives the connection |

```rust
// Dial a host someone else is running
let client = connect("unix:/tmp/ante.sock".parse()?, ConnectOptions::default()).await?;
```

Plain `ws://` is dialed only to loopback hosts. Remote hosts need `wss://`, behind the opt-in `wss` feature, so the token never crosses a network in cleartext.

Every field of `ConnectOptions` is optional: `executable` (defaults to `ante` on `PATH`), `args` appended after `serve --stdio`, `cwd`, extra `env`, and `token`. A successful `connect` means the pipe opened or the socket dialed. There is no greeting, so the reply to your first op is the liveness check.

A process that hosts sessions itself gets the same `Client` type from its host directly, carrying the same wire types, so client code works unchanged in either setup.

## Worked examples

- [`examples/mini-tui`](https://github.com/AntigmaLabs/ante/tree/main/examples/mini-tui) is a chat TUI in one file. It streams `MessageDelta`s, answers `TurnPause` approvals with `y`/`n`, and sends `Interrupt` on Esc. Run it with `cargo run` from that directory.
- [`examples/ante-gateway`](https://github.com/AntigmaLabs/ante/tree/main/examples/ante-gateway) is a Slack and Discord bot that gives each thread or DM its own session on a shared host. See [Gateway Mode](/usage/gateway) to run it.

## Ops and events

The SDK re-exports the protocol types as `ante_sdk::protocol`. The [Protocol Reference](/reference/protocol-reference) lists every op and event, and [`ante serve`](/usage/serve) covers the host side: transports, socket ownership, and limits.
