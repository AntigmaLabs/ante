[Offline mode](/local/offline) works out of the box with the engine Ante installs and supervises. You can replace the binary, customize model and GPU options, or attach a server you run yourself.

## Use your own llama.cpp build

Ante resolves the engine binary in this order:

1. A binary path pinned in `offline-config.json` (below)
2. The managed `~/.ante/llama.cpp/current/llama` multiplexer

Ante does not discover an arbitrary PATH installation for managed mode. To use your own build, point `llama_cpp.binaries.server` at its `llama` multiplexer in `~/.ante/offline-config.json`:

```json
{
  "llama_cpp": {
    "binaries": {
      "server": "/opt/llama.cpp/build/bin/llama"
    }
  }
}
```

The file must exist and support `llama serve`. Older saved paths ending in `llama-server` automatically resolve to a sibling `llama`, so existing managed installs migrate without a config rewrite. If that sibling multiplexer does not exist, install the supported engine with `ante offline install` or update the custom path.

:::note
Ante normally writes these fields itself during installation. If you point them at a custom build, the version check may offer an "upgrade" back to the pinned build — decline it to keep yours.
:::

## Tune managed inference {#tune-the-launch-command}

Two knobs shape managed inference:

**Per-model extra flags.** Set `extra_args` in a model's [preferences](/local/offline#model-preferences) to add llama.cpp model options. The string is parsed shell-style (quoting works) and translated into that model's router preset, so a supplied value overrides Ante's model default without restarting the shared server:

```json
{
  "model_preferences": {
    "Qwen3.6-27B-Q4_K_M.gguf": {
      "model_id": "Qwen3.6-27B-Q4_K_M.gguf",
      "extra_args": "--threads 12 --no-mmap --cache-type-k q8_0"
    }
  }
}
```

Router-owned or identity-changing options such as `--host`, `--port`, `--model`, and `--alias` are rejected. Malformed values also fail explicitly instead of producing a preset whose effective context, temperature, or reasoning state differs from what Ante reports.

**GPU offload.** `llama_cpp.server_defaults.gpu_layers` controls the `-ngl` value. The default `-1` offloads all layers to the GPU; lower it if your VRAM is tight:

```json
{
  "llama_cpp": {
    "server_defaults": { "gpu_layers": 24 }
  }
}
```

## Attach to a running server

You can run `llama-server` entirely yourself — any build, any flags — and let
Ante connect to it as a client. Ante scans local ports **8080-8179** and also
supports manual `host:port` attach from `/offline-mode` with `Ctrl+A`.

See [Existing Servers](/local/existing-servers) for endpoint input, Docker
examples, detach behavior, and the remote-host data-flow caveat.

## A different engine entirely

Anything with an OpenAI-compatible endpoint — Ollama, vLLM, LM Studio, a GPU box on your LAN — can serve Ante as a regular catalog provider. That route gives you provider mechanics only (model picker, wire protocol); the lifecycle management, memory estimation, and load progress on this page are specific to the managed llama.cpp path. See [add a local provider](/usage/providers#add-a-local-provider-with-no-auth).
