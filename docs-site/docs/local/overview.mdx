# Self-Contained by Design

Ante is a single self-contained binary (a ~15MB compressed download) that manages its own inference engine. Add a GGUF file and you have a complete coding agent on your own hardware: no API key, no account, and model calls that never leave your machine.

:::note Privacy boundary
Local inference keeps model requests and responses on your hardware. Ante application telemetry is separate from model traffic; set `ANTE_TELEMETRY=off` for runs where no OpenTelemetry metrics or logs should be exported. This does not disable local log files. See [Telemetry](/configuration/preference#telemetry).
:::

Local is a first-class way to run Ante. Hosted and local providers live in the same catalog, run the same full prompt and tool stack, and go through the same [public benchmarks](/benchmarks/eval). You choose per session which one a task deserves.

## Pick your topology

| Topology | What it looks like | Reach for it when |
|---|---|---|
| **All frontier** | Hosted providers only | You want peak capability and have connectivity and budget |
| **Mixed** | Local and hosted side by side, switched per session or mid-conversation | Some work is privacy-sensitive or high-volume, some needs a frontier model |
| **All local** | The built-in engine serves everything | Air-gapped machines, hard privacy requirements, zero marginal cost |

## How Ante treats local models

**A provider like any other.** Any local server with an OpenAI-compatible endpoint (Ollama, vLLM, LM Studio, your own) registers through the same `catalog.json` mechanism as a hosted provider. No special casing, and nothing to migrate away from later. See [local provider setup](/reference/catalog-reference#add-a-local-provider-with-no-auth) and the [Catalog Reference](/reference/catalog-reference).

**Native integration.** Ante goes further than tolerating a base URL. [Offline mode](/local/offline) manages llama.cpp itself: pinned, checksum-verified builds matched to your hardware (Metal on Apple silicon, CUDA or Vulkan or CPU on Linux), GGUF discovery across your disk, memory estimation before a model loads, live load progress, and server lifecycle handled in the TUI. A [curated model list](/local/verified-models) tells you what runs well before you download 17 GB. Prefer your own build or launch flags? [Custom engines](/local/custom-engines) covers that.

**Agent-native inference, in progress.** The endgame is an inference engine inside the agent process, tuned for how agents actually call models: prefix reuse across turns, constrained decoding for tool calls, batching across subagents. We explore that in the open with [nanochat-rs](https://github.com/AntigmaLabs/nanochat-rs), a small pure-Rust inference core you can clone and run. See [Agent-Native Inference](/experimental/agent-native-inference).

## Mixing local and frontier

When offline mode loads a model, Ante registers it as the `local` provider: an ordinary OpenAI-compatible entry in the catalog, next to Anthropic or OpenAI. From there, mixing is normal provider mechanics:

- **Switch mid-session.** `/providers` in the TUI switches provider and model without a restart. Draft against a frontier model, flip to local for a sensitive repo, flip back.
- **Pick per invocation.** `ante --offline-model <file>` runs a script or headless job against a local model while other sessions use hosted providers.
- **Share one model across clients.** `ante serve --offline-model <path>` loads the model once for every connecting client, and any session can [attach to a llama server](/local/existing-servers) already running on your machine (ports 8080-8179 are scanned automatically).
- **Lighter models for subagents.** A [subagent](/extend/subagents) can pin its own model id via `model:` frontmatter, so exploration or search agents can run on a smaller model than the main loop.

One boundary to know: a session talks to one provider at a time. Switching is instant, but a subagent runs on its parent session's provider, so you cannot yet route the main loop to a frontier provider and a subagent to `local` within the same session. A separate Ante process has no such limit, and the next example uses one.

### Keep sensitive files on a local subagent {#local-subagent}

A main agent on a hosted model can hand a sensitive file to Ante on a local model and work from what comes back. The main agent can be Claude Code, Codex, or an Ante session on a hosted provider. Say it needs to analyze `tickets.csv`, a support export that holds customer names, emails, and phone numbers. It runs:

```bash
ANTE_TELEMETRY=off ante --offline-model --no-session-save --tools Read,Write \
  -p "Read tickets.csv. Write tickets.redacted.csv with the same rows and columns, replacing every person name, email address, and phone number with [NAME], [EMAIL], and [PHONE]. Reply with only the number of rows written."
```

The local model reads the export and writes the redacted copy. The main agent gets back a row count, then analyzes `tickets.redacted.csv`. A row from the result:

```csv
1003,[NAME],[EMAIL],[PHONE],"Login loop on Safari after the last update. My colleague [NAME] sees it too."
```

Each part of the command narrows where the data can go:

- `--offline-model` starts the default saved with [`ante offline use`](/local/offline#configure-without-the-tui), so the file's contents go to a model on your hardware.
- `--tools Read,Write` gives the subagent file access only: no shell, web, or MCP tools.
- `--no-session-save` skips the transcript, which would keep a copy of what the model read under `~/.ante/sessions/`.
- `ANTE_TELEMETRY=off` turns off metric and log export. See [Telemetry](/configuration/preference#telemetry).

Two things stay in your hands. Everything the subagent prints returns to the main agent and its hosted model, so ask for a reply that is safe to share, such as a count. The main agent also has to leave the original file unread and pass only its path. A local model can miss a name, so spot-check the redacted file before a hosted model reads it.

The curated [`ante` skill](https://github.com/AntigmaLabs/ante/tree/main/curated/skills/ante) teaches other agents this pattern, along with the other ways to run Ante as a subagent.
