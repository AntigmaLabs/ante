## Prerequisites

Have a provider account or API key handy. To run a model on your own machine, follow the [offline setup](/local/offline).

## Installation

Ante is distributed as a single, self-contained binary with no external dependencies — just download and run.

```sh
curl -fsSL https://ante.run/install.sh | bash
```

By default this installs to `~/.ante/bin` and configures your shell's `PATH`. Open a new terminal to run `ante`, or use `~/.ante/bin/ante` immediately in the current terminal. Run `ante --version` to check the installation; this guide targets **v0.3.4**.

To install somewhere else, set `ANTE_INSTALL_DIR`:

```sh
curl -fsSL https://ante.run/install.sh | ANTE_INSTALL_DIR=/usr/local/bin bash
```

Run the default installer as your normal user, not with `sudo`. A sudoed home-directory install would leave `~/.ante` root-owned and prevent Ante from saving settings and input history, so the installer refuses that combination.

macOS release binaries are Developer ID-signed and notarized, so Gatekeeper accepts them without a manual security bypass.

## Run your first task {#start-with-your-existing-account-or-key}

<span id="interactive-session" />

Open a terminal in your project and start Ante:

```bash
cd your-project
ante
```

<span id="use-a-different-provider" />

If you’ve already signed in or exported your API key in this shell, send a prompt. For a first connection, open `/providers`, select your provider, and press `m` to sign in or paste a key. See [Connect a provider](/usage/providers).

Try asking Ante to trace a path through the code:

> Where does this project start? Show me the entry point and a test that exercises it.

Press `Enter` and watch which files Ante reads. Then ask “How do I run just that test?” in the same session. To point Ante at a particular file, type `@` and choose it from the list.

### Sign in to Antix from the CLI {#log-in-with-antix}

From your project directory, run `ante auth login antix`, finish signing in through the browser, then run `ante --provider antix` to start the same task.

## Quick examples

### Headless one-shot

```bash
# Run a task and exit
ante -p "add error handling to src/main.rs"
```

### Pipe input from stdin

```bash
# Pipe file contents for analysis
cat src/lib.rs | ante -p "review this code for bugs"
```

### Skip tool approvals

```bash
# YOLO mode — auto-approve all tool calls
ante --yolo -p "fix all clippy warnings"
```

### Run as a server

```bash
# Start a long-lived daemon for programmatic integration
ante serve
```

### Update to the latest version

```bash
# Check for a new release and install it
ante update

# Try the development channel for one update
ante update nightly

# Roll back or pin to an exact release
ante update --version v0.3.4
```
