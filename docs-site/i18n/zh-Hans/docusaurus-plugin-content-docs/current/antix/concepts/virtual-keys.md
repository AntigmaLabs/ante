# 虚拟密钥和硬性预算

永远不要分发原始的提供商密钥。Antix 会签发**虚拟密钥（Virtual Keys）**，它们充当中间件拦截器，在将流量路由至上游之前对预算进行原子级验证。

## 创建密钥

可以直接从 Antix 门户网站仪表板（位于 [https://portal.antigma.ai](https://portal.antigma.ai)）生成密钥。

创建密钥时，您可以设置：
- **密钥名称（Key Name）：** 用于在门户网站和追踪中标识该密钥的标签。
- **预算（Budget）：** 可选的硬性支出上限（`max_budget`，单位为美元）。目前没有按天/月/生命周期的周期选择器——这是一个单一的固定上限。

密钥被安全地存储——明文只在创建时返回**一次**。门户网站签发的密钥以 **`sk-antix-…`** 开头。

:::note
针对每个密钥的模型允许列表（allow-lists）和针对每个密钥的速率限制（rpm/tpm）目前尚未在门户网站的密钥创建流程中提供。请参阅 [错误处理](/zh-Hans/antix/concepts/error-handling) 以了解网关当前的（全局，非每密钥）速率限制。
:::

## 可靠的计费

Antix 严格执行预算以防止超额。在任何请求发送至上游之前，成本会被估算并保留。如果一个请求会导致超出该密钥的 `max_budget`（最大预算），该请求将立即被拒绝，并返回 `402 Payment Required` 错误。

一旦请求完成或被取消，成本将被准确地对账。这种严格的执行消除了双重支出（double-spending），并确保您的预算上限得到严格遵守，即使在繁重的并发负载下也是如此。
