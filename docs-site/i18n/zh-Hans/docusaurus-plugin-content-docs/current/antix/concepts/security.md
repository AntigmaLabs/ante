# 隐私、安全与数据留存

Antix 的设计以 **故障关闭计费（fail-closed billing）** 和 **凭据隔离（credential isolation）** 为核心，而不是一揽子的零数据留存。请向您的团队明确说明平台会持久化哪些数据，以使合规期望与现实相符。

## Antix 会持久化什么

- **请求和响应主体** 会在每次代理调用时被记录，以用于成本归因、重试安全性以及管理员的分析时间轴。这是一个部署层面的决定，目前并不是一个可以选择开启的开关。
- **计费事件** — 代币数量、模型、用户、组织、虚拟密钥标识符、首代币时间（TTFT）、持续时间 — 都会被安全地持久化。
- **身份状态** — OAuth 会话、刷新令牌家族以及黑名单条目 — 会被持久化以用于会话管理和权限撤销。

如果您的合规要求需要对有效载荷进行脱敏，请向管理您 Antix 部署的人员提出——脱敏通常在日志接收端处理，或者通过在脱敏网关后运行 Antix 来实现。Antix 目前不提供内置的有效载荷清除开关。

## Antix 不会做什么

- **不进行模型训练。** 流经 Antix 的流量绝不会用于训练 Antigma 的模型。不过，您仍需验证所路由的每个上游提供商针对每个模型的数据政策。
- **不在日志中泄露凭据。** 虚拟密钥被安全地存储；明文仅在创建时返回一次。
- **没有静默的未计费流量。** 如果计费后端不可达，Antix 会以 `503` 故障关闭，而不是去处理它无法计量的请求。
