## 概览 {#overview}

Ante 采用清晰的职责分离设计，遵循客户端-守护进程（Client-Daemon）架构。展示层与核心执行引擎通过消息传递进行解耦，使得切换终端前端（TUI、无头 CLI）时无需变动底层核心引擎。

## 客户端与守护进程划分 {#client-daemon-split}

```
┌────────────────┐          ┌─────────────────────────────┐
│     Client     │    Op    │          Daemon             │
│                │ ───────▶ │                             │
│  TUI / Headless│          │  Session ─▶ Turn ─▶ Step    │
│  或 Serve 服务  │ ◀─────── │                             │
│                │    Evt   │  Tools    Providers   Store │
└────────────────┘          └─────────────────────────────┘
```

- **Client（客户端）** — 用户面向层。基于 ratatui 的 TUI 终端界面、无头 CLI 运行器，或通过 `ante serve` 连接的外部进程。负责发送 `Op` 操作指令并渲染接收到的 `Evt` 事件。
- **Daemon（守护进程）** — 核心引擎。接收操作指令、管理会话、分发大语言模型请求、调度工具安全执行并分发事件。
- **Transport（传输层）** — 进程内客户端（TUI、无头模式）使用 Tokio 通道；外部客户端通过 `ante serve` 使用基于 stdio、Unix 套接字或 WebSocket 的 JSONL 协议。详见[传输层](/reference/protocol-reference#transport)。

[通信协议参考手册](/reference/protocol-reference)定义了全部操作指令与事件。

## 大语言模型提供商 {#llm-providers}

Ante 不绑定特定提供商。启动会话时，Ante 根据命令行选项或已保存的偏好确定提供商、模型与凭据。提供商适配器把对话与工具调用转换为相应的 API 格式，再把回复转换为会话事件。

流式传输中的偶发故障会在轮次内自动重连。调用停滞时，会在按提供商配置的空闲窗口后超时，可通过 [`stream_idle_timeout_secs`](/reference/catalog-reference#provider-fields) 设置。登录与密钥配置参见[连接提供商](/usage/providers)。

## 工具系统 {#tool-system}

守护进程执行模型请求的工具调用，执行前先按[权限规则](/configuration/permission)检查。内置工具涵盖文件 I/O、Shell、网络访问、子智能体与结构化提问；[MCP 服务器](/extend/mcp)可提供更多工具。各工具说明、默认工具集与过滤参数参见[工具参考](/reference/tools-reference)。

## 会话生命周期 {#session-lifecycle}

1. 客户端发送 `Op::StartSession`（包含模型、提供商与策略配置）
2. 守护进程解析提供商、验证认证状态，并发现技能与子智能体
3. 守护进程创建 `Session` 并发出 `Evt::SessionStart`
4. 用户发送 `Op::UserInput` 开始一个轮次
5. 会话拉起 `Turn` 轮次与大语言模型通信
6. 轮次执行工具调用、请求用户审批并最终完成输出
7. 当对话接近上下文上限时，Ante 会[压缩](/reference/protocol-reference#concepts)较早的历史
