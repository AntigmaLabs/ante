Ante 可以作为交互式 TUI、一次性无头（Headless）命令、长时间运行的协议服务器或通道网关运行。

```bash
ante [OPTIONS] [COMMAND]
```

## 命令 (Commands)

| 命令 (Command) | 描述 (Description) |
|---|---|
| `ante` | 启动交互式 TUI。如果提供了 `-p` / `--prompt`，则以无头模式运行。 |
| `ante serve` | 运行一个长时间活跃的 JSONL 或 WebSocket 协议服务器。 |
| `ante gateway` | 运行 Slack / Discord 通道网关。 |
| `ante update` | 检查是否有最新的 Ante 发布版，如果可用则安装。 |
| `ante rage` | 收集经过脱敏的错误报告包（日志 + 环境）以便与 Ante 团队共享。 |
| `ante catalog` | 将加载的提供商/模型 Catalog 打印为 JSON。 |
| `ante doctor` | 运行启动时的自我检查，并报告启动阶段的耗时。 |

## `ante`

```bash
ante [OPTIONS]
```

如果不带 `--prompt`，Ante 会启动交互式 TUI。带有 `--prompt`，Ante 会运行一个无头任务然后退出。

| 标志位 (Flag) | 描述 (Description) |
|---|---|
| `-m`, `--model <MODEL>` | 覆盖默认的模型名称。 |
| `--provider <PROVIDER>` | 按 Catalog 提供商名称覆盖 API 提供商。 |
| `--yolo` | 在会话中跳过工具批准提示。 |
| `--permission-mode <MODE>` | 覆盖本次运行的权限模式：`strict`、`auto` 或 `yolo`。与 `--yolo` 冲突。 |
| `--system-prompt <PROMPT>` | 完全替换默认系统提示词。 |
| `--append-system-prompt <TEXT>` | 将内容追加到默认系统提示词中。 |
| `--enable-auto-memory` | 为本次运行启用自动记忆。与 `--disable-auto-memory` 冲突。 |
| `--disable-auto-memory` | 为本次运行禁用自动记忆。与 `--enable-auto-memory` 冲突。 |
| `--include-tools <TOOLS>...` | 仅允许这些工具。值之间用空格分隔。`--tools` 是简写别名；`--allowed-tools` 是已废弃但仍起作用的别名，会打印警告。 |
| `--exclude-tools <TOOLS>...` | 从会话中移除这些工具。值之间用空格分隔。`--disallowed-tools` 是已废弃但仍起作用的别名，会打印警告。 |
| `--output-format <FORMAT>` | 无头模式输出格式：`json`、`human` 或 `minimal`。默认为 `minimal`。 |
| `-p`, `--prompt <PROMPT>` | 在无头模式下运行的提示词。当通过管道传输时，也支持从 stdin 读取。 |
| `--check` | 在无头任务完成后运行验证检查。 |
| `-r`, `--resume <SESSION_ID>` | 按 ID 恢复先前的会话。 |
| `--offline-model <PATH>` | 用于离线推理的本地 GGUF 模型文件路径。 |
| `-h`, `--help` | 打印命令帮助。 |
| `-V`, `--version` | 打印 Ante 版本。 |

### 示例

```bash
ante
ante -p "解释这个项目是做什么的"
git diff | ante -p "审查此 diff 中的 bug"
ante --provider openai --model gpt-5.5 -p "重构数据库模块"
ante --resume ses_01ARZ3NDEKTSV4RRFFQ69G5FAV -p "现在添加测试"
ante -p "总结这个仓库" --enable-auto-memory
```

## `ante serve`

```bash
ante serve [OPTIONS]
```

服务器模式默认通过 stdin/stdout 暴露 Ante 协议，或在提供 `--ws` 时通过 WebSocket 暴露。

| 标志位 (Flag) | 描述 (Description) |
|---|---|
| `--stdio` | 通过 stdin/stdout 提供 JSONL 协议服务。这是默认的传输方式。 |
| `--ws <ADDR>` | 在给定的套接字地址上通过 WebSocket 提供协议服务。与 `--stdio` 冲突。 |
| `--offline-model <PATH>` | 启动时加载本地 GGUF 模型以进行离线模式。 |
| `-h`, `--help` | 打印命令帮助。 |

:::note
`serve` 是与会话无关的，因此它不接受会话标志（`--model`、`--provider`、`--yolo`、`--system-prompt`、`--include-tools` 等）。连接的客户端会通过协议为每个会话配置这些设置。
:::

### 示例

```bash
ante serve
ante serve --ws 127.0.0.1:8080
```

## `ante gateway`

```bash
ante gateway [OPTIONS]
```

网关模式使用通道配置文件将 Ante 连接到 Slack、Discord 或两者。

| 标志位 (Flag) | 默认值 | 描述 (Description) |
|---|---|---|
| `--config <PATH>` | `~/.ante/channels.json` | 通道配置文件的路径。 |
| `--model <MODEL>` | `local` | Agent 会话中使用的模型。 |
| `--provider <PROVIDER>` | `local` | Agent 会话中使用的提供商。 |
| `--output-format <FORMAT>` | `minimal` | Gateway stdout 输出格式：`json`、`human` 或 `minimal`。 |
| `--offline-model <PATH>` | - | 为所有网关对话加载一个本地 GGUF 模型。 |
| `-h`, `--help` | - | 打印命令帮助。 |

### 示例

```bash
ante gateway
ante gateway --provider anthropic --model claude-sonnet-4-6
ante gateway --config ./channels.json --output-format human
```

## `ante update`

```bash
ante update [OPTIONS] [CHANNEL]
```

update 命令检查是否有更新的 Ante 发布版并在可用时安装。如果不带参数，它会跟随存储在 `~/.ante/settings.json` 中的通道（默认为 `stable`）。传递一个通道 —— 作为位置参数或通过 `--channel` 传递 —— 会仅为本次运行覆盖被追踪的通道。有关完整的通道列表，请参阅 [更新与通道](/start/update)。

| 参数 (Argument) | 描述 (Description) |
|---|---|
| `[CHANNEL]` | 用于更新的发布通道（`stable` 或 `nightly`）。接受 `latest` 作为 `stable` 的遗留别名。与 `--channel` 和 `--version` 冲突。 |

| 标志位 (Flag) | 描述 (Description) |
|---|---|
| `--channel <CHANNEL>` | 用于更新的发布通道。等效于位置形式。 |
| `--version <VERSION>` | 安装确切版本而不是通道的最新发布版。接受带或不带前导 `v` 的值，例如 `v0.preview.33` 或 `0.preview.33`。与通道参数冲突。 |
| `-h`, `--help` | 打印命令帮助。 |

### 示例

```bash
ante update
ante update nightly
ante update --channel stable
ante update --version v0.preview.33
```

## `ante rage`

```bash
ante rage [OPTIONS]
```

当出现问题时，`ante rage` 会将 Ante 团队调查所需的上下文收集到一个单一的可共享存档中，您可以将其附加到 GitHub Issue 中。默认情况下，它会写入 `./ante-rage-<timestamp>.tar.gz` 并打印一份简短摘要。没有任何内容会被上传 —— 在您分享之前，数据包一直保留在本地。

在写入任何内容之前，密码和密钥会被脱敏。API 密钥和 OAuth 令牌只会报告为存在/不存在（绝不会出现其值），URL 中嵌入的凭证和已知格式的令牌会被掩码隐藏，对话转录和系统提示词会被排除，`~/.ante/auth/*.json` 和 `channels.json` 绝不会被包含在内。

存档包含：

| 文件 | 内容 |
|---|---|
| `report.md` | Ante 版本、操作系统/架构、shell、git 分支、解析的模型/提供商、提供商认证表（存在/不存在）以及脱敏声明。 |
| `env.txt` | 与 Ante 相关的环境变量。安全值会原样显示；已知密码仅显示为 `<SET>` / `<UNSET>`。 |
| `settings.redacted.json` | 移除了密码的 `~/.ante/settings.json`（MCP 服务器凭据被剥离）。 |
| `catalog.redacted.json` | 移除了密码的 `~/.ante/catalog.json`，仅在自定义 Catalog 存在时包含。 |
| `logs/` | 最近的应用程序和崩溃日志，经过过滤和清理。`DEBUG`/`TRACE` 行会被丢弃，因此请求体永远不会进入数据包。 |

默认情况下会收集最新的日志，最多 10 个文件或 10 MB（崩溃日志始终优先）。使用 `--since` 可以收集时间窗口内的所有内容。

| 标志位 (Flag) | 描述 (Description) |
|---|---|
| `--output <PATH>` | 将数据包写入此路径，而不是 `./ante-rage-<timestamp>.tar.gz`。 |
| `--no-compress` | 保持暂存文件夹未压缩，而不是生成 `.tar.gz`。 |
| `--verbose-logs` | 同时也包含 `DEBUG`/`TRACE` 日志行。对话转录和系统提示词依然会被排除。 |
| `--since <DURATION>` | 收集窗口内修改过的每个日志，忽略文件数量和大小限制。接受 `<n>d`、`<n>h`、`<n>m`，或裸数字天数（例如 `7d`、`48h`、`90m`、`2`）。 |
| `-h`, `--help` | 打印命令帮助。 |

### 示例

```bash
ante rage
ante rage --output ./ante-bug.tar.gz
ante rage --since 7d
ante rage --no-compress
```

## `ante catalog`

```bash
ante catalog
```

将合并后的提供商/模型 Catalog（内置预设加上 `~/.ante/catalog.json`）作为 JSON 打印到 stdout，使用与 Catalog 文件相同的模式。被跳过的 Catalog 条目的警告会输出到 stderr，因此 stdout 保持为干净的 JSON 文档，可以通过管道传给 `jq`。关于模式 (Schema) 请参考 [Catalog 参考](/reference/catalog-reference)。

### 示例

```bash
ante catalog
ante catalog | jq '.providers | keys'
```

## `ante doctor`

```bash
ante doctor
```

启动与真实启动相同的运行时 —— 加载合并的 Catalog、启动守护进程会话并渲染首个 TUI 帧 —— 然后打印一份包含各阶段耗时的就绪报告。用它来确认 Ante 已正确安装和配置，或作为 CI 冒烟测试（"Ante 是否启动，首帧是否渲染"）。

它不需要 TTY 也不需要 API 密钥：会跳过 MCP 预热，会话仅凭 Catalog 即可达到就绪状态。报告列出三个检查 —— `catalog`（提供商/模型数量）、`session`（解析后的 `provider/model`）和 `first frame`（无头渲染）—— 后面是总耗时。警告（如没有已认证的提供商、跳过的 Catalog 条目或 `settings.json` 解析提示）会列在表格下方，而不会导致检查失败。如果任何硬性检查失败，`doctor` 会以非零退出，因此它在脚本中可用。

### 示例

```bash
ante doctor
ante doctor || echo "ante is not healthy"
```

## 输出格式 (Output Formats)

| 格式 (Format) | 描述 (Description) |
|---|---|
| `minimal` | 仅打印 Agent 消息、信息和错误。 |
| `human` | 以人类可读格式打印所有事件。 |
| `json` | 将事件打印为 JSON 行以便机器处理。 |
