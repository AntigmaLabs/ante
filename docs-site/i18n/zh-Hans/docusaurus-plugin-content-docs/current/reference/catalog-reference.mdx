Ante 通过**目录 (catalog)**来解析每一个提供商和模型：本文档所列即为内置的预设配置，在启动时将结合您位于 [`~/.ante/catalog.json`](#catalogjson-schema) 的自定义配置共同生效。目录配置在每个进程生命周期内只被读取一次 — 若有修改请重启 Ante 生效。

本页为详尽参考指南。有关日常如何选择提供商及直接复制粘贴的配置示例，请参阅[提供商](/usage/providers)。

## 各提供商的模型 {#models-by-provider}

每个提供商附带了一组 `preferred_models`（首选模型） — 这些就是模型选择器中显示的 ID。当您指定了某提供商但未命名模型时，Ante 默认使用其**量级最重 (heaviest-weight)** 的模型（参阅[量级分类](#weight-classes)），而不是简单地选取列表里的第一个模型。显式选择提供商具有绝对权威性：如果您传入了 `--provider`，Ante 会将您给出的模型 ID 发送至该提供商，即便该 ID 并未在其 `preferred_models` 中列出（参阅[解析过程](#how-a-model-and-provider-are-chosen)）。

#### OpenAI 传输协议 {#openai-transports}

`openai` 及 `openai-subscription` 提供商支持以两种方式流式传输响应：

| 传输协议 | 端点 | 默认 |
|---|---|---|
| `http_sse` (HTTP + SSE) | `https://api.openai.com/v1/responses` (或对应的订阅端点) | ✅ |
| `websocket_auto` (持久化 WebSocket) | `wss://.../v1/responses` | 可选 |

WebSocket 模式会为每一次会话保持单一连接始终打开，并利用 `previous_response_id` 附加新的输入项来继续对话。在较长的智能体工具循环中，这消除了每一轮往返延迟。详细底层协议信息，请参阅 OpenAI 的 [WebSocket 模式指南](https://developers.openai.com/api/docs/guides/websocket-mode)。

通过配置进程范围的环境变量进行选用（默认为 `http_sse`）：

```bash
ANTE_OPENAI_TRANSPORT=websocket_auto ante --provider openai --model gpt-5-mini
```

支持的值包括：`http_sse`, `websocket_auto`。未知的参数将触发警告并回退至 `http_sse`。

注意事项：

- WS 模式只在流式传输轮次（如 TUI 会话）中生效。在基于设计的无头 `--prompt` 模式下将使用非流式 `chat()` 并自动绕过 WS。
- 任何瞬间发生的 WS 故障（连接超时、网络波动）在当轮都会自动降级至 HTTP/SSE — 借此用户永远不会遇到因传输层选择造成的硬性报错。若遇到认证失败 (`401`/`403`)，系统会将当前会话之后的流程直接回退为 HTTP/SSE。
- 该功能在访问 `api.openai.com` (API-key) 以及位于 `chatgpt.com/backend-api/codex` 的 ChatGPT 订阅后端的应用上皆可正常运作。
- 如何验证启用的协议模式：在 debug 编译版中，开启 debug 浮窗（`Ctrl+L`）并在 **Info** 选项卡下查看 `OpenAI Transport:` 一行；或者可以直接用 grep 筛选您的会话日志来寻找 `transport selected` 的记录：

  ```bash
  grep "transport selected" ~/.ante/logs/ante.*.log.*
  ```

## `catalog.json` 模式 {#catalogjson-schema}

每次启动时，`~/.ante/catalog.json` 都会合并到内置预设之上。它有两个可选的顶层键，都是按 id 索引的映射：

```json
{
  "providers": { /* 增加或重写提供商 */ },
  "models":    { /* 覆盖对应现有模型字段值 */ }
}
```

如果 `providers` 中的键匹配内置提供商（例如 `openai`），该条目会逐字段修补内置预设；新键会新增一个提供商。映射键就是传给 `--provider` 的 id，因此每个条目的 `id` 应与外层键保持一致。

:::note
可以通过 `ANTE_HOME` 环境变量改变默认的 `~/.ante` 工作目录；catalog 文件始终位于 `$ANTE_HOME/catalog.json`。
:::

### 提供商相关字段 {#provider-fields}

| 字段 | 必填项 | 描述 |
|---|---|---|
| `id` | ✅ | 提供商 ID。必须与映射键一致（`name` 仍作为旧别名接受）。这也是传给 `--provider` 的值。 |
| `display_name` | 对新增提供商：选填 | TUI 中显示的友好名称。新增提供商省略时默认使用提供商 id。 |
| `base_url` | 对新增提供商：✅ | API 提供商的基础 URL。 |
| `wire_style` | 对新增提供商：✅ | Ante 与该提供商通信时使用的协议形态，例如 `AnthropicMessage`、`OpenAiCompatible`、`OpenAiResponse` 或 `Gemini`。 |
| `auth` | — | 认证配置，说明凭据从哪里读取。详见[认证方式](#authentication)。省略时表示无需认证。 |
| `http_headers` | — | 附加到每个请求的 HTTP 头，格式为字符串键值映射。 |
| `supports_web_search` | — | 该提供商是否支持原生 Web 搜索。为 `true` 时，Ante 会自动为此提供商的会话加入 `WebSearch` 工具；默认 `false`。 |
| `preferred_models` | — | 模型选择器中显示的模型列表，也用于默认模型选择。详见[模型字段](#model-fields)。覆盖内置提供商时，匹配的模型 id 会被修补，新 id 会追加到列表末尾；省略则保留内置列表。 |

```json
{
  "providers": {
    "my-provider": {
      "id": "my-provider",
      "display_name": "My Provider",
      "base_url": "https://api.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "auth": { "bearer": { "env_key": "MY_PROVIDER_API_KEY" } },
      "http_headers": { "X-Org": "my-team" },
      "preferred_models": [
        {
          "id": "my-model",
          "description": "My fine-tuned model",
          "max_tokens": 32000,
          "context_limit": 200000,
          "thinking": "Enabled"
        }
      ]
    }
  }
}
```

修改内置提供商时，只需要写入想改变的字段。可选字段设为 `null` 会清除预设值，这在把提供商指向本地代理、且不希望发送内置认证或头部时很有用：

```json
{
  "providers": {
    "openai": {
      "base_url": "http://localhost:8080/v1",
      "auth": null,
      "http_headers": null
    }
  }
}
```

### 认证方式 {#authentication}

`auth` 是一个带标签的对象：标签决定凭据发送到哪里，凭据本身可以来自环境变量（`env_key`），也可以来自 Ante 内置的 OAuth 登录流程（`oauth_preset`）。

| 形式 | JSON 代码 | 发送形式 |
|---|---|---|
| Bearer token（不记名令牌） | `{ "bearer": { "env_key": "MY_KEY" } }` | `Authorization: Bearer <token>` |
| 自定义头部 (Custom header) | `{ "header": { "name": "x-api-key", "env_key": "MY_KEY" } }` | `<name>: <token>` |
| Query 参数 | `{ "query": { "name": "api_key", "env_key": "MY_KEY" } }` | `?<name>=<token>` |

把 `env_key` 换成 `oauth_preset` 后，Ante 会通过内置 OAuth 流程认证，而不是读取环境变量。可用预设包括 `anthropic`、`openai` 和 `antix`：

```json
"auth": { "bearer": { "oauth_preset": "anthropic" } }
```

只要凭据存在，提供商就会被视为已认证：环境变量已设置且非空，或 OAuth token 已保存在磁盘上。没有 `auth` 配置的提供商始终视为已认证。未认证的提供商会在自动检测时跳过，并在选择器中排到后面。

### 模型字段 {#model-fields}

同一组字段既可以在提供商的 `preferred_models` 中完整描述模型（此时必须提供 `id`），也可以在顶层 `models` 中局部覆盖模型（此时映射键就是 id）。除 id 外，其余字段都是可选的：

| 字段 | 描述 |
|---|---|
| `id` | 模型 ID。在 `preferred_models` 中必填（`name` 仍作为旧别名接受）；在顶层 `models` 中由映射键提供。 |
| `display_name` | 友好的显示名称。 |
| `description` | 模型选择器中显示的简短说明。 |
| `temperature` | 采样温度。 |
| `top_p` | Nucleus sampling 的截断阈值。 |
| `top_k` | Top-k sampling 的候选数量上限。 |
| `max_tokens` | 每轮最大输出 token 数。 |
| `stop_sequences` | 触发生成停止的字符串列表。 |
| `context_limit` | 上下文窗口大小，单位为 token。 |
| `thinking` | 推理强度，可选值为 `Disabled`、`Enabled`、`Deep` 或 `Max`。 |
| `weight_class` | 模型的规模/成本档位，可选 `Feather`、`Middle` 或 `Heavy`。Ante 会据此选择默认模型和辅助调用模型。详见[量级分类](#weight-classes)。 |
| `support_vision` | 模型是否接受图片输入。省略时，Ante 会根据模型 id 推断；如果向不支持视觉的模型读取图片，只会返回图片元数据，而不会发送像素内容。 |

顶层 `models` 会按模型 id 修补已知模型，并在解析模型时覆盖到规范配置之上。内置预设默认不写任何覆盖项：

```json
{
  "models": {
    "claude-sonnet-4-6": { "thinking": "Deep", "max_tokens": 64000 }
  }
}
```

### 量级分类 {#weight-classes}

每个内置模型都有 `weight_class`：`Feather`（小、快、成本低）、`Middle`（折中）或 `Heavy`（最大、能力最强）。当用户没有明确指定模型时，Ante 会用它来自动选型。

- **默认模型** — 只选择提供商、不显式指定模型时，会解析为该提供商下最重的模型。
- **辅助调用** — `WebFetch` 页面摘要等成本较低的内部任务，会使用该提供商下最轻的模型。

没有设置 `weight_class` 的模型会回退到 catalog 顺序。给自定义模型设置 `weight_class` 后，也会参与这些选择规则。

## 提供商与模型是如何被选取的 {#how-a-model-and-provider-are-chosen}

Ante 解析模型 ID 时会叠加三个来源，后面的优先级更高：

1. **规范配置** — catalog 顺序中第一个在 `preferred_models` 里列出该 id 的提供商。未知 id 会回退到一个最小的默认模型配置。
2. **`models` 覆盖** — 如果顶层 `models` 中有该 id 的局部补丁，则应用这些字段。
3. **环境变量覆盖** — 下方列出的进程环境变量优先于所有配置。

提供商也会参与模型匹配。如果只传 `--model`，Ante 会优先选择一个已认证、且 `preferred_models` 中包含该模型 id 的提供商；找不到时，退回到第一个已认证且没有 `preferred_models` 限制的提供商；再找不到则使用默认提供商。

如果同时传 `--provider` 和 `--model`，只要指定提供商已认证，显式提供商选择就会生效。Ante 仍会先按全局模型 id 解析配置，因此已知模型即使由另一个提供商承载，也会继承 catalog 元数据和用户覆盖；未知模型则按最小默认配置直接透传。

如果没有传 `--model` 或 `--provider`，Ante 会自动检测：按 catalog 顺序选择第一个已认证的提供商，并使用该提供商下最重的模型（见[量级分类](#weight-classes)）。如果没有任何提供商通过认证，则回退到 `local`。

## 环境变量覆盖机制 {#environment-overrides}

这些进程级环境变量会覆盖当前会话的 catalog 值，无需修改配置文件：

| 变量名称 | 改写的对象目标 |
|---|---|
| `MODEL_BASE_URL` | 所有提供商的基础 URL（如果存在 `ANTHROPIC_BASE_URL` 这类提供商专属变量，则专属变量优先）。 |
| `MODEL_TEMPERATURE` | `temperature` |
| `MODEL_TOP_P` | `top_p` |
| `MODEL_MAX_TOKENS` | `max_tokens` |
| `MODEL_CONTEXT_LIMIT` | `context_limit` |
| `MODEL_THINKING` | `thinking`，可选 `none`、`enabled`、`deep` 或 `max`。 |

多个内置预设还支持专属基础 URL 环境变量，并且它们优先于通用的 `MODEL_BASE_URL`：`ANTHROPIC_BASE_URL`、`OPENAI_BASE_URL`、`OPENAI_COMPATIBLE_BASE_URL` 和 `DEEPSEEK_BASE_URL`。

## 错误处理 {#error-handling}

单个配置条目出错不会导致整个文件失效。Ante 会宽松解析 `catalog.json`：任何无法反序列化的提供商或模型条目都会被跳过，其余内容仍会加载。被跳过的条目会在启动时报告，例如：

```
Skipped 1 entry in ~/.ante/catalog.json:
  - providers.my-provider: missing field `base_url`
```

只有当文件本身不是 JSON 对象时，Ante 才会直接拒绝加载。缺少 `catalog.json` 不是错误，Ante 会使用内置预设。
