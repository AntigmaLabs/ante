Ante 从一个 **catalog**（目录）解析每个提供商和模型：此处记录的内置预设，在启动时与您的 [`~/.ante/catalog.json`](#catalogjson-schema) 合并。Catalog 在每个进程中只读取一次 —— 重启 Ante 以使修改生效。

此页面是详尽的参考。关于如何在日常中选择提供商以及复制粘贴自定义配置配方，请参阅 [Providers](/zh-Hans/configuration/providers)。

## 按提供商分类的模型

每个提供商都附带一组 `preferred_models` —— 在模型选择器中显示的 id。当您选择一个提供商但未指定模型时，Ante 默认使用其 **最高权重**（heaviest-weight）模型（参见 [权重级别](#weight-classes)），而不仅仅是列表中的第一个。显式的提供商选择具有权威性：如果您传递了 `--provider`，即使您提供的模型 id 未列在 `preferred_models` 中，Ante 也会将其发送给该提供商（参见 [解析规则](#how-a-model-and-provider-are-chosen)）。

#### OpenAI 传输协议 {#openai-transports}

`openai` 和 `openai-subscription` 提供商可以通过两种方式流式传输响应：

| 传输协议 (Transport) | 终端点 (Endpoint) | 默认 |
|---|---|---|
| `http_sse` (HTTP + SSE) | `https://api.openai.com/v1/responses` (或订阅对应地址) | ✅ |
| `websocket_auto` (持久 WebSocket) | `wss://.../v1/responses` | 需要开启 |

WebSocket 模式每个会话保持一个打开的连接，并继续每个回合，仅包含 `previous_response_id` 加上新的输入项。在漫长的 Agent 工具循环中，这消除了每回合的往返延迟。有关底层协议，请参阅 OpenAI 的 [WebSocket 模式指南](https://developers.openai.com/api/docs/guides/websocket-mode)。

通过进程作用域的环境变量开启（默认为 `http_sse`）：

```bash
ANTE_OPENAI_TRANSPORT=websocket_auto ante --provider openai --model gpt-5-mini
```

接受的值：`http_sse`、`websocket_auto`。未知值会发出警告并回退到 `http_sse`。

注意：

- WS 仅在流式传输回合（TUI 会话）中启用。无头（Headless）`--prompt` 模式使用非流式的 `chat()` 并按照设计绕过 WS。
- 任何瞬时的 WS 失败（连接超时、网络波动）在当前回合都会回退到 HTTP/SSE —— 用户永远不会看到由传输选择引起的硬错误。认证失败（`401`/`403`）会在会话剩余的生命周期中将整个会话切换为 HTTP/SSE。
- 对 `api.openai.com` (API 密钥) 和 ChatGPT 订阅后端 `chatgpt.com/backend-api/codex` 均有效。
- 要验证哪个传输协议处于活动状态：在 debug 构建中，切换调试面板（`Ctrl+L`）并检查 **Info** 选项卡中的 `OpenAI Transport:` 行。否则可以在您的会话日志中通过 grep 查找 `transport selected`：

  ```bash
  grep "transport selected" ~/.ante/logs/ante.*.log.*
  ```

## `catalog.json` 模式 (Schema) {#catalogjson-schema}

`~/.ante/catalog.json` 在启动时覆盖合并在内置预设之上。它有两个可选的顶级键，都是以 id 为键的映射：

```json
{
  "providers": { /* 添加或覆盖提供商 */ },
  "models":    { /* 覆盖现有模型上的字段 */ }
}
```

其键与内置匹配的 `providers` 条目（如 `openai`）会逐字段修补该预设；新的键会添加一个提供商。映射键是您传递给 `--provider` 的内容，因此请保持每个条目的 `id` 与其键相等。

:::note
可以使用环境变量 `ANTE_HOME` 重新定位 `~/.ante`；Catalog 始终是 `$ANTE_HOME/catalog.json`。
:::

### 提供商字段 (Provider fields)

| 字段 | 是否必需 | 描述 |
|---|---|---|
| `id` | ✅ | 提供商 id。必须匹配映射键（接受 `name` 作为遗留别名）。这是您传递给 `--provider` 的内容。 |
| `display_name` | 新提供商: 可选 | TUI 中显示的友好名称。省略时，新提供商默认使用提供商 id。 |
| `base_url` | 新提供商: ✅ | API 基础 URL。 |
| `wire_style` | 新提供商: ✅ | Ante 使用的 API 协议方言 —— `AnthropicMessage`、`OpenAiCompatible`、`OpenAiResponse` 或 `Gemini`。 |
| `auth` | — | 如何进行身份验证（参见 [认证方式](#authentication)）。对于不需要密钥的提供商请省略。 |
| `http_headers` | — | 每个请求附带的额外标头，作为 string→string 映射。 |
| `supports_web_search` | — | 提供商是否公开原生的网络搜索功能。当为 `true` 时，`WebSearch` 工具会自动添加到此提供商的会话中；当为 `false`（默认）时，不提供 `WebSearch`。 |
| `preferred_models` | — | 此提供商在选择器中显示的模型，用作提供商默认值（参见 [模型字段](#model-fields)）。对于内置提供商的覆盖，匹配的模型 id 被修补，新的 id 被追加；省略将保持预设列表不变。 |

```json
{
  "providers": {
    "my-provider": {
      "id": "my-provider",
      "display_name": "My Provider",
      "base_url": "https://api.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "auth": { "bearer": { "env_key": "MY_PROVIDER_API_KEY" } },
      "http_headers": { "X-Org": "my-team" },
      "preferred_models": [
        {
          "id": "my-model",
          "description": "我的微调模型",
          "max_tokens": 32000,
          "context_limit": 200000,
          "thinking": "Enabled"
        }
      ]
    }
  }
}
```

对于内置提供商，只包含您想要更改的字段。带有 `null` 的可选字段会清除预设值，这在将提供商指向不应发送内置凭据或标头的本地代理时很有用：

```json
{
  "providers": {
    "openai": {
      "base_url": "http://localhost:8080/v1",
      "auth": null,
      "http_headers": null
    }
  }
}
```

### 认证方式 (Authentication) {#authentication}

`auth` 是一个带标签的对象：标签选择凭据的位置，凭据要么是环境变量（`env_key`），要么是 Ante 的内置 OAuth 流程（`oauth_preset`）之一。

| 形式 | JSON | 发送内容 |
|---|---|---|
| Bearer token | `{ "bearer": { "env_key": "MY_KEY" } }` | `Authorization: Bearer <token>` |
| 自定义 Header | `{ "header": { "name": "x-api-key", "env_key": "MY_KEY" } }` | `<name>: <token>` |
| Query 参数 | `{ "query": { "name": "api_key", "env_key": "MY_KEY" } }` | `?<name>=<token>` |

将 `env_key` 替换为 `oauth_preset` 以通过内置 OAuth 流程（`anthropic`、`openai` 或 `antix`）而不是环境变量进行身份验证：

```json
"auth": { "bearer": { "oauth_preset": "anthropic" } }
```

当提供商的凭据存在时 —— 环境变量已设置且非空，或者磁盘上存在 OAuth 令牌 —— 该提供商即被视为已认证。没有 `auth` 块的提供商始终被视为已认证。未认证的提供商在自动检测期间会被跳过，并在选择器中显示在最后。

### 模型字段 (Model fields) {#model-fields}

相同的字段描述可以完全包含在提供商的 `preferred_models` 内部（此处需要 `id`），或部分位于 `models` 节点下（映射键提供 id）。除 id 之外的每个字段都是可选的：

| 字段 | 描述 |
|---|---|
| `id` | 模型 id。在 `preferred_models` 中是必需的（接受 `name` 作为遗留别名）；在 `models` 下由映射键提供。 |
| `display_name` | 友好名称。 |
| `description` | 显示在模型选择器中的简短描述。 |
| `temperature` | 采样温度。 |
| `top_p` | Nucleus 采样截断值。 |
| `top_k` | Top-k 采样截断值。 |
| `max_tokens` | 每回合的最大输出 token 数。 |
| `stop_sequences` | 结束生成的字符串列表。 |
| `context_limit` | 上下文窗口大小，以 token 数表示。 |
| `thinking` | 推理量级 —— `Disabled`、`Enabled`、`Deep` 或 `Max`。 |
| `weight_class` | 规模/成本层级 —— `Feather`、`Middle` 或 `Heavy`。驱动自动默认及辅助模型选择（参见 [权重级别](#weight-classes)）。 |
| `support_vision` | 模型是否接受图像输入。如果省略，Ante 从模型 id 推断；对没有视觉支持的模型读取图像将返回图像的元数据而不是其像素。 |

`models` 部分在任何定义的地方通过 id 修补模型，在解析时层叠在规范定义之上。内置预设使其保持为空：

```json
{
  "models": {
    "claude-sonnet-4-6": { "thinking": "Deep", "max_tokens": 64000 }
  }
}
```

### 权重级别 (Weight classes) {#weight-classes}

每个内置模型都带有一个 `weight_class` —— `Feather`（小/快/便宜）、`Middle` 或 `Heavy`（最大/能力最强）。Ante 使用它来在您不指定名称的情况下挑选模型：

- **默认模型** —— 选择没有明确指定模型的提供商时，解析为其 **最高权重** 的模型。
- **辅助调用** —— 廉价的内部工作（如 `WebFetch` 页面摘要）使用提供商的 **最低权重** 模型。

未设置 `weight_class` 的模型退回到 Catalog 的顺序。在自定义模型上设置 `weight_class` 以引导这些选择。

## 模型和提供商的选择解析规则 {#how-a-model-and-provider-are-chosen}

当 Ante 解析模型 id 时，它分三层来源，以后者为准：

1. **规范定义** —— Catalog 顺序中第一个在其 `preferred_models` 列出该 id 的提供商。未知的 id 退回使用裸默认定义。
2. **`models` 覆盖** —— 您针对该 id 的部分修补（如果有）。
3. **环境变量覆盖** —— 下面的进程环境变量优先于一切。

提供商也与模型匹配。如果只传递 `--model`，Ante 会挑选一个已认证且其 `preferred_models` 列表中包含该 id 的提供商，退而求其次挑选一个已认证但没有 `preferred_models` 的提供商，再然后退回至默认提供商。

如果同时传递了 `--provider` 和 `--model`，明确的提供商选择只要认证过就会优先。Ante 仍会首先全局解析模型 id，因此已知的 id 会继承 Catalog 的元数据和用户覆盖，即使由不同提供商提供；未知的 id 将作为裸模型定义直接透传。

当没有传递 `--model`/`--provider` 时，Ante 进行自动检测：它按照 Catalog 顺序使用第一个已认证的提供商及其最高权重模型（参见 [权重级别](#weight-classes)），如果都没有认证则回退到 `local`。

## 环境变量覆盖

这些进程环境变量会为当前会话覆盖 Catalog 值，而无需编辑文件：

| 变量 | 覆盖字段 |
|---|---|
| `MODEL_BASE_URL` | 所有提供商的 Base URL（特定提供商的变量如 `ANTHROPIC_BASE_URL` 具有更高优先级）。 |
| `MODEL_TEMPERATURE` | `temperature` |
| `MODEL_TOP_P` | `top_p` |
| `MODEL_MAX_TOKENS` | `max_tokens` |
| `MODEL_CONTEXT_LIMIT` | `context_limit` |
| `MODEL_THINKING` | `thinking` —— 接受 `none`、`enabled`、`deep` 或 `max` |

一些预设还遵守特定的 Base URL 环境变量，它们优先于 `MODEL_BASE_URL`：`ANTHROPIC_BASE_URL`、`OPENAI_BASE_URL`、`OPENAI_COMPATIBLE_BASE_URL`、`DEEPSEEK_BASE_URL`。

## 错误处理

不良的条目不会让整个文件失效。Ante 会宽容地解析 `catalog.json`：任何反序列化失败的提供商或模型条目会被跳过，而其余条目仍会加载。跳过的条目在启动时会被报告，例如：

```
Skipped 1 entry in ~/.ante/catalog.json:
  - providers.my-provider: missing field `base_url`
```

只有完全不是 JSON 对象的文件才会被直接拒绝。缺少 `catalog.json` 是可以的 —— Ante 仅仅使用内置预设。
