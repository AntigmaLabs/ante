Ante 在客户端和守护进程（Daemon）之间使用一种强类型的消息传递协议。消息通过有界的异步通道（进程内）交换，或作为 JSON 行 (JSON Lines) 通过 stdin/stdout 交换（外部客户端）。

## 协议格式 (Wire format)

外部客户端使用 **JSON Lines** (JSONL) 与守护进程通信 —— 通过 stdin/stdout 每行一个 JSON 对象。

- **客户端 → 守护进程**：将 `OpMsg` 对象作为 JSON 行发送到 stdin
- **守护进程 → 客户端**：从 stdout 接收 `EventMsg` 对象作为 JSON 行

### OpMsg 封套 (envelope)

每个操作都包装在一个 `OpMsg` 中：

```json
{
  "op": { "StartSession": { "model": "claude-sonnet-4-6", "provider": "anthropic" } },
  "id": "op_01ARZ3NDEKTSV4RRFFQ69G5FAV"
}
```

### EventMsg 封套

每个事件都包装在一个 `EventMsg` 中：

```json
{
  "timestamp": "2025-06-01T12:00:00Z",
  "id": "evt_01ARZ3NDEKTSV4RRFFQ69G5FAV",
  "event": { "AgentMessage": "结果如下..." },
  "parent": "op_01ARZ3NDEKTSV4RRFFQ69G5FAV"
}
```

`parent` 字段将事件链接回触发它的操作。当不适用时，它为 `null`。

## 消息 ID

每条消息都有一个带类型的 `Id`，由前缀（最多 4 个字节）和 [ULID](https://github.com/ulid/spec) 组成。字符串格式为 `{prefix}_{ulid}`。

| 前缀 | 用途 |
|---|---|
| `op_` | 操作（客户端 → 守护进程） |
| `evt_` | 事件（守护进程 → 客户端） |
| `ses_` | 会话标识符 |
| `step_` | 步骤 (Step) 标识符 |

示例：`op_01J5A3B7C9D0E1F2G3H4J5K6M7`

## 操作 (Client → Daemon)

### StartSession

使用模型、提供商和配置初始化新会话。

```json
{
  "op": {
    "StartSession": {
      "model": "claude-sonnet-4-6",
      "provider": "anthropic",
      "permission_mode": null,
      "system_prompt": null,
      "append_system_prompt": null,
      "include_tools": null,
      "exclude_tools": null,
      "cwd": null,
      "thinking": null,
      "enable_auto_memory": null
    }
  },
  "id": "op_..."
}
```

**SessionConfig 字段：**

| 字段 | 类型 | 描述 |
|---|---|---|
| `model` | `string` | 模型名称（例如 `"claude-sonnet-4-6"`） |
| `provider` | `string` | 提供商名称（例如 `"anthropic"`, `"openai"`, `"gemini"`, `"xai"`, `"openrouter"`, `"local"`） |
| `permission_mode` | `PermissionMode?` | 工具审批模式：`"strict"`、`"auto"` 或 `"yolo"`。`null` 时使用 `"strict"` |
| `system_prompt` | `string?` | 完全覆盖默认的系统提示词 |
| `append_system_prompt` | `string?` | 将内容追加到默认系统提示词中 |
| `include_tools` | `string[]?` | 白名单 —— 只有这些工具可用。也会拦截动态注册的 (MCP) 工具 |
| `exclude_tools` | `string[]?` | 黑名单 —— 这些工具会被移除 |
| `cwd` | `string?` | 工作目录。默认为守护进程所在的目录 |
| `thinking` | `Thinking?` | 思考级别覆盖：`"Disabled"`、`"Enabled"`、`"Deep"` 或 `"Max"` |
| `enable_auto_memory` | `bool?` | Agent 是否记录和回忆 [自动记忆 (auto-memory)](/extend/memory)。`null` 时保留守护进程默认值（交互式会话开启） |

### UpdateSession

无需重启即就地更新活跃会话（例如在会话中途切换模型或权限模式）。每个字段都是可选的；缺失的字段保持不变。权限模式的更改 —— 即 TUI 中按 `Shift+Tab` 循环发送的内容 —— 立即生效，应用于正在进行的当前回合以及后续回合；模型更改则在下一回合生效。其他会话选项必须在 `StartSession` 时设置。

```json
{
  "op": {
    "UpdateSession": {
      "model": { "name": "gpt-5.4", "temperature": 0.2 },
      "permission_mode": "auto"
    }
  },
  "id": "op_..."
}
```

**SessionUpdate 字段：**

| 字段 | 类型 | 描述 |
|---|---|---|
| `model` | `ModelSpec?` | 要使用的新模型规范 |
| `permission_mode` | `PermissionMode?` | 新权限模式（`"strict"`、`"auto"` 或 `"yolo"`） |

### ResumeSession

通过 ID 恢复先前持久化的会话。守护进程会还原对话历史、重新发现扩展应用，并重放最近的事件，以便客户端可以重建其视图。

```json
{ "op": { "ResumeSession": { "session_id": "ses_01ARZ..." } }, "id": "op_..." }
```

| 字段 | 类型 | 描述 |
|---|---|---|
| `session_id` | `Id` | 要恢复的会话标识符 |

成功时，守护进程会为当前会话（如果有）发出 `SessionEnd`，然后发出恢复会话的 `SessionStart` 和 `ExtensionRefreshed`，接着是最多 200 个重放的历史事件。失败时会发出 `Error` 事件。

### Steer

在活跃的回合进行中向 Agent 提供额外引导，而无需启动新的一回合。

```json
{ "op": { "Steer": "首先专注于 auth 模块" }, "id": "op_..." }
```

### UserInput

向 Agent 提交用户文本输入。

```json
{ "op": { "UserInput": "解释这个项目是做什么的" }, "id": "op_..." }
```

### ApprovalResponse

响应工具审批请求（在收到原因为 `Approval` 的 `TurnPause` 事件后发送）。

```json
{
  "op": {
    "ApprovalResponse": {
      "turn_id": "step_01ARZ...",
      "responses": [
        ["tool_use_abc123", "Accept"],
        ["tool_use_def456", "Skip"]
      ]
    }
  },
  "id": "op_..."
}
```

**ReviewDecision 值：**

| 决定 (Decision) | 描述 (Description) |
|---|---|
| `Accept` | 允许此工具调用 |
| `Skip` | 跳过此工具调用 |
| `AcceptForSession` | 在会话的剩余时间内授予此调用权限（有范围限制 —— 参见 [会话授权](/configuration/permission#session-grants)） |
| `AcceptAlways` | 为会话授予权限并将允许规则持久化到 `settings.json`（"始终允许"） |
| `Abort` | 终止当前任务 |

### SlashCommand

通过名称调用一项技能 (Skill)。

```json
{ "op": { "SlashCommand": { "name": "commit", "args": "-m '修复 bug'" } }, "id": "op_..." }
```

### Interrupt

终止当前正在运行的任何内容。

```json
{ "op": "Interrupt", "id": "op_..." }
```

### Shutdown

请求优雅的关闭。

```json
{ "op": "Shutdown", "id": "op_..." }
```

### RegisterLocalProvider

注册一个正在运行的本地推理服务器（例如客户端启动的离线 `llama-server`）作为该守护进程的 `local` 提供商。模型是可选的 —— 如果提供了模型，它将把本地提供商固定到特定的 `ModelSpec`；否则，本地提供商将提供该服务器托管的任何模型。

```json
{
  "op": {
    "RegisterLocalProvider": {
      "port": 8080,
      "model": null
    }
  },
  "id": "op_..."
}
```

| 字段 | 类型 | 描述 |
|---|---|---|
| `port` | `u16` | 本地 llama-server 正在监听的端口 |
| `model` | `ModelSpec?` | 可选的模型规范，用于固定提供商 |

### RestoreLocalProvider

在会话级别的提供商切换之后，恢复之前注册的本地提供商配置。当守护进程需要还原到之前注册的本地服务器，而无需重新提供其端口和模型时非常有用。

```json
{ "op": "RestoreLocalProvider", "id": "op_..." }
```

## 事件 (Daemon → Client)

### 会话事件 (Session events)

#### SessionStart

会话初始化时发出。包含有关活跃模型、提供商、会话 ID 和工作目录的元数据。技能和子代理通过 `ExtensionRefreshed` 单独投递。

```json
{
  "event": {
    "SessionStart": {
      "model": { "name": "claude-sonnet-4-6", "max_tokens": 8192 },
      "provider": "anthropic",
      "session_id": "ses_01ARZ...",
      "cwd": "/home/user/project",
      "permission_mode": "strict"
    }
  }
}
```

**SessionInitialized 字段：**

| 字段 | 类型 | 描述 |
|---|---|---|
| `model` | `ModelSpec` | 活跃模型规范 |
| `provider` | `string` | 活跃提供商名称（例如 `"anthropic"`） |
| `session_id` | `Id` | 唯一的会话标识符 |
| `cwd` | `string` | 工作目录路径 |
| `permission_mode` | `PermissionMode` | 活跃的权限模式（`"strict"`、`"auto"` 或 `"yolo"`） |

#### SessionUpdated

当活跃会话被就地更新（例如通过 `UpdateSession` 更改了模型）时发出。

```json
{
  "event": {
    "SessionUpdated": {
      "model": { "name": "gpt-5.4" },
      "provider": "openai",
      "session_id": "ses_01ARZ...",
      "cwd": "/home/user/project"
    }
  }
}
```

#### SessionEnd

会话终止时发出。

```json
{ "event": "SessionEnd" }
```

### 回合生命周期事件 (Turn lifecycle events)

#### TurnStart

新的回合开始处理时发出。

```json
{ "event": { "TurnStart": { "turn_id": "step_01ARZ..." } } }
```

#### TurnPause

回合暂停等待用户输入（例如工具审批）时发出。

```json
{
  "event": {
    "TurnPause": {
      "turn_id": "step_01ARZ...",
      "reason": {
        "Approval": {
          "tools": [
            { "id": "tool_use_abc123", "name": "Bash", "input": { "command": "ls -la" } }
          ],
          "message": "允许运行 shell 命令吗？"
        }
      }
    }
  }
}
```

**TurnPauseReason 变体：**

| 变体 (Variant) | 字段 (Fields) | 描述 (Description) |
|---|---|---|
| `Approval` | `tools: ToolUse[]`, `message: string` | 等待工具审批 |

#### TurnEnd

回合完成时发出。

```json
{ "event": { "TurnEnd": { "turn_id": "step_01ARZ...", "status": "Completed" } } }
```

**TurnEndStatus 变体：**

| 变体 (Variant) | 字段 (Fields) | 描述 (Description) |
|---|---|---|
| `Completed` | — | 回合成功完成 |
| `Interrupted` | `reason?: string` | 回合被中断 |
| `Error` | `message: string` | 回合因错误结束 |

### 消息流事件 (Message streaming events)

#### AgentMessage

完整的 Agent 文本响应（非流式）。

```json
{ "event": { "AgentMessage": "该项目是一个 Web 服务器，它..." } }
```

#### Thinking

完整的思维链 (chain-of-thought) 块（非流式）。

```json
{ "event": { "Thinking": "让我分析一下代码库结构..." } }
```

#### MessageDelta

Agent 消息的流式块。将所有增量连接起来以构建完整的消息。

```json
{ "event": { "MessageDelta": "该项目" } }
```

#### ThinkingDelta

Agent 思维过程的流式块。将所有增量连接起来以构建完整的思考块。

```json
{ "event": { "ThinkingDelta": "让我" } }
```

### 工具事件 (Tool events)

#### ToolStart

工具调用开始时发出。

```json
{
  "event": {
    "ToolStart": {
      "id": "tool_use_abc123",
      "name": "Read",
      "input": { "file_path": "/src/main.rs" }
    }
  }
}
```

#### ToolUpdate

工具执行期间的进度更新。

```json
{
  "event": {
    "ToolUpdate": {
      "tool_use_id": "tool_use_abc123",
      "seq": 0,
      "message": "正在读取文件..."
    }
  }
}
```

| 字段 | 类型 | 描述 |
|---|---|---|
| `tool_use_id` | `string` | 工具调用标识符（匹配 `ToolStart.id`） |
| `seq` | `u64` | 单调递增的序列号 |
| `message` | `string` | 进度消息 |

#### ToolEnd

工具执行完成时发出。

```json
{
  "event": {
    "ToolEnd": {
      "tool_use_id": "tool_use_abc123",
      "status": "Completed",
      "result_json": { "content": "fn main() { ... }" },
      "is_error": false
    }
  }
}
```

**ToolEndStatus 变体：**

| 变体 (Variant) | 描述 (Description) |
|---|---|
| `Completed` | 工具成功运行 |
| `Cancelled` | 工具执行被取消 |
| `Denied` | 工具被用户拒绝 |
| `Failed` | 工具执行失败 |

### 压缩事件 (Compaction events)

#### CompactStart

对话压缩开始时发出。

```json
{ "event": "CompactStart" }
```

#### CompactEnd

对话压缩完成时发出。

```json
{ "event": "CompactEnd" }
```

### 扩展事件 (Extension events)

#### ExtensionRefreshed

当技能 (skills)、子代理 (subagents) 或 MCP 服务器刷新时发出。在正常会话期间至少发送两次：一次在带有初始技能/子代理（且 `mcp_servers: []`）的 `SessionStart` 之后发出，另一次在 MCP 后台预热完成并获取到发现的服务器和工具列表后发出。

```json
{
  "event": {
    "ExtensionRefreshed": {
      "session_id": "ses_01ARZ...",
      "skills": [
        { "name": "commit", "description": "创建一个 git commit", "scope": "user", "argument_hint": "-m 'message'" }
      ],
      "subagents": [
        { "name": "explore", "description": "探索代码库", "scope": "project" }
      ],
      "mcp_servers": [
        {
          "name": "filesystem",
          "command": "npx",
          "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
          "tools": [
            {
              "name": "read_text_file",
              "qualified_name": "mcp__filesystem__read_text_file",
              "description": "读取文本文件的内容",
              "parameters": [
                { "name": "path", "param_type": "string", "required": true, "description": "文件的路径" }
              ]
            }
          ]
        }
      ]
    }
  }
}
```

`mcp_servers` 中的每个条目都反映了实际启动和发现的内容：对于连接失败的服务器，`tools` 列表为空；而 `qualified_name` 是 Agent 调用该工具时使用的 `mcp__<server>__<tool>` 形式。

### 信息事件 (Informational events)

#### UsageUpdate

会话的 token 使用统计信息。在第一次响应之前或模型上下文限制未知时，会省略 `context`。它仅包含原始测量值 —— `used_tokens`（包含缓存的窗口占用量）和 `limit_tokens`（模型原始的上下文限制）；任何百分比均由客户端计算得出。当提供商上报时，`usage` 还可能包含 `cache_read_tokens` 和 `cache_creation_tokens`。

```json
{
  "event": {
    "UsageUpdate": {
      "usage": { "input_tokens": 1500, "output_tokens": 300 },
      "context": { "used_tokens": 1800, "limit_tokens": 200000 }
    }
  }
}
```

#### Info

常规的信息性消息。

```json
{ "event": { "Info": "正在压缩对话历史记录..." } }
```

#### InfoBlockStart

打开一个带标题的分组 Info 条目。随后的共享相同 `id` 的 `InfoBlockAppend` 事件会在其下方呈现为树状缩进的子行 —— 用于应当在视觉上聚合成块的多步骤后台通知（例如 MCP 预热）。

```json
{
  "event": {
    "InfoBlockStart": {
      "id": "mcp-warmup-ses_01ARZ...",
      "header": "正在后台预热 4 个 MCP 服务器 —— 工具将在连接后变得可用。"
    }
  }
}
```

#### InfoBlockAppend

将子详细信息行追加到具有相同 `id` 的 `InfoBlockStart` 中。如果没有匹配的块，则静默丢弃。

```json
{
  "event": {
    "InfoBlockAppend": {
      "id": "mcp-warmup-ses_01ARZ...",
      "detail": "MCP 就绪：4/4 个服务器已连接，60 个工具已注册。"
    }
  }
}
```

#### Error

错误消息。

```json
{ "event": { "Error": "认证失败：无效的 API 密钥" } }
```

#### Goodbye

守护进程断开连接前的最后一条消息。收到此消息后，将不再发送任何事件。

```json
{ "event": "Goodbye" }
```

#### UserInput

为会话回放记录的用户输入。此变体被写入持久化的事件日志中，但 **不会** 在实时会话中发出 —— 您只能在 `ResumeSession` 的事件回放中看到它。

```json
{ "event": { "UserInput": "解释这个项目是做什么的" } }
```

### 离线模式与协议 (Offline mode and the protocol)

本地模型的管理（引擎安装、模型发现、llama-server 生命周期）是 **客户端侧** 的。它是通过进程内的 `OfflineSubsystem` API 驱动的，而不是通过守护进程协议。离线模式唯一面向守护进程的协议层面是 `RegisterLocalProvider` / `RestoreLocalProvider` —— 客户端自己启动 llama-server，然后向守护进程注册其端口（以及可选的 `ModelSpec`）。

请参阅 [离线模式](/zh-Hans/experimental/offline) 页面了解面向用户的流程及 `--offline-model` CLI 标志。

## 传输协议 (Transport)

### 进程内通道 (In-process channels)

当客户端和守护进程在同一进程（TUI 或无头模式）中运行时，它们通过有界的 Tokio mpsc 通道进行通信：

| 通道 (Channel) | 方向 (Direction) | 缓冲区大小 (Buffer size) |
|---|---|---|
| Op channel | 客户端 → 守护进程 | 256 条消息 |
| Event channel | 守护进程 → 客户端 | 4096 条消息 |

### Stdio 传输协议 (JSONL)

对于使用 `ante serve`（或 `ante serve --stdio`）的外部客户端，`StdioTransport` 将通过 stdin/stdout 的 JSON Lines 桥接到内部通道对：

- **stdin** → 将每一行解析为 `OpMsg` → 转发给守护进程
- **daemon events** → 序列化为 JSON → 写入 **stdout**（每个事件一行）
- **stdin 上出现 EOF** → 自动发送 `Op::Shutdown`
- **接收到 `Evt::Goodbye`** → 传输退出
- **JSON 解析错误** → 会将 `Evt::Error` 在 stdout 返回

### WebSocket 传输协议

对于使用 `ante serve --ws <ADDR>` 的联网或基于浏览器的客户端，`WsTransport` 通过 WebSocket 帧交换相同的 JSONL 协议：

- 每个 WebSocket 连接获得自己的守护进程实例
- 消息是相同的 `OpMsg` 和 `EventMsg` JSON 对象，作为文本帧发送
- **客户端断开连接** → 守护进程实例关闭，服务器接受下一个连接
- **接收到 `Op::Shutdown`** → 连接和服务器一起退出
- 服务器会循环接受新连接，直到接收到 `Shutdown` 为止

## 完整流程示例

从启动到关闭的完整会话生命周期：

```
客户端                                  守护进程
  │                                       │
  │─── OpMsg { StartSession(...) } ──────▶│
  │◀── EventMsg { SessionStart(...) } ────│
  │                                       │
  │─── OpMsg { UserInput("修复 bug") } ───▶│
  │◀── EventMsg { TurnStart { turn_id } } │
  │◀── EventMsg { ThinkingDelta("...") }  │
  │◀── EventMsg { ThinkingDelta("...") }  │
  │◀── EventMsg { Thinking("...") }       │
  │◀── EventMsg { MessageDelta("...") }   │
  │◀── EventMsg { ToolStart(ToolUse) }    │
  │◀── EventMsg { TurnPause(Approval) }   │
  │                                       │
  │─── OpMsg { ApprovalResponse(...) } ──▶│
  │◀── EventMsg { ToolUpdate(...) }       │
  │◀── EventMsg { ToolEnd(...) }          │
  │◀── EventMsg { MessageDelta("...") }   │
  │◀── EventMsg { AgentMessage("...") }   │
  │◀── EventMsg { UsageUpdate(...) }      │
  │◀── EventMsg { TurnEnd(Completed) }    │
  │                                       │
  │─── OpMsg { Shutdown } ───────────────▶│
  │◀── EventMsg { SessionEnd }            │
  │◀── EventMsg { Goodbye }               │
  │                                       │
```
