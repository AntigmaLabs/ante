---
title: "代理组织（实验性）"
description: "用于编排协作 AI 代理的多代理架构模式"
---

Ante 支持多种模式来组织代理协同工作。每种架构都在自主性、协调开销和结果质量之间进行权衡。

## Independent（独立模式）

代理们并行处理同一个问题，彼此之间没有交互。聚合器在最后综合它们的输出。

**最适合：** 多样化独立视角能提高质量的任务（头脑风暴、冗余验证）。

```mermaid
flowchart TB
  classDef control fill:#e1f5ff,stroke:#4aa3df,color:#00324d;
  classDef agent fill:#fff4e6,stroke:#e0a96d,color:#4a2c00;
  classDef agg fill:#e6f3ff,stroke:#6ea8fe,color:#002b55;

  Start([开始]) --> Fanout{{并行分发}}
  Fanout --> A1[代理 1]
  Fanout --> A2[代理 2]
  Fanout --> A3[代理 3]

  A1 --> Barrier{{屏障 / 同步}}
  A2 --> Barrier
  A3 --> Barrier

  Barrier --> Agg[聚合器<br/>综合]
  Agg --> End([结束])

  class Fanout,Barrier control;
  class A1,A2,A3 agent;
  class Agg agg;
```

## Decentralized（去中心化模式）

代理们在并行的轮次中运行，读取彼此先前的输出并提出完善建议。经过固定数量的轮次后，在没有中央协调者的情况下形成共识。

**最适合：** 辩论式推理、同行评审，或者不应该由单一权威主导的谈判。

```mermaid
flowchart TB
  classDef control fill:#e1f5ff,stroke:#4aa3df,color:#00324d;
  classDef agent fill:#fff4e6,stroke:#e0a96d,color:#4a2c00;
  classDef state fill:#f3f4f6,stroke:#9ca3af,color:#111827;
  classDef decision fill:#ffe6f0,stroke:#f472b6,color:#4a044e;

  Start([开始]) --> Init[初始化]
  Init --> Board[(共享看板<br/>迄今为止的提案)]

  Board --> Fanout{{并行：读取并提议}}
  Fanout --> A1[代理 1<br/>读取看板<br/>+ 提议变更]
  Fanout --> A2[代理 2<br/>读取看板<br/>+ 提议变更]
  Fanout --> A3[代理 3<br/>读取看板<br/>+ 提议变更]

  A1 --> Barrier{{屏障 / 同步}}
  A2 --> Barrier
  A3 --> Barrier

  Barrier --> Merge[将变更追加<br/>到看板]
  Merge --> Board

  Board --> Stop{{停止？<br/>达到轮次限制或收敛}}
  Stop -->|否| Fanout
  Stop -->|是| Consensus[从看板<br/>形成共识]
  Consensus --> End([结束])

  class Fanout,Barrier control;
  class A1,A2,A3 agent;
  class Board state;
  class Stop decision;
```

## Centralized Iterative（集中迭代模式）

一个中央编排器分解问题，并行分发代理，评估它们的结果，并决定是继续完善还是结束。

**最适合：** 受益于具有质量关卡的自上而下规划的复杂任务（带有代码审查的代码生成、多步骤研究）。

```mermaid
flowchart TB
  classDef control fill:#e1f5ff,stroke:#4aa3df,color:#00324d;
  classDef agent fill:#fff4e6,stroke:#e0a96d,color:#4a2c00;
  classDef orch fill:#e6f3ff,stroke:#6ea8fe,color:#002b55;
  classDef eval fill:#ffe6e6,stroke:#fb7185,color:#4c0519;
  classDef state fill:#f3f4f6,stroke:#9ca3af,color:#111827;
  classDef decision fill:#ffe6f0,stroke:#f472b6,color:#4a044e;

  Start([开始]) --> Setup[设置]
  Setup --> Workspace[(工作空间<br/>任务 + 结果)]

  Workspace --> Orch[编排器<br/>分解 / 完善计划]
  Orch --> Fanout{{并行：执行任务}}
  Fanout --> A1[代理 1]
  Fanout --> A2[代理 2]
  Fanout --> A3[代理 3]

  A1 --> Barrier{{屏障 / 同步}}
  A2 --> Barrier
  A3 --> Barrier

  Barrier --> Write[将结果写入<br/>工作空间]
  Write --> Workspace

  Workspace --> OrchEval[编排器<br/>评估质量]
  OrchEval --> Stop{{完成？}}
  Stop -->|否：继续完善| Orch
  Stop -->|是| Final[最终<br/>综合]
  Final --> End([结束])

  class Fanout,Barrier control;
  class A1,A2,A3 agent;
  class Orch orch;
  class OrchEval eval;
  class Workspace state;
  class Stop decision;
```

## Hybrid Iterative（混合迭代模式）

将集中编排与去中心化的同行审查相结合。编排器规划并分发代理，然后代理在一个同行评审轮次中相互完善彼此的工作，之后编排器再进行评估。

**最适合：** 结构化规划和同行反馈同等重要的高质量协作输出（协作写作、架构设计）。

```mermaid
flowchart TB
  classDef control fill:#e1f5ff,stroke:#4aa3df,color:#00324d;
  classDef agent fill:#fff4e6,stroke:#e0a96d,color:#4a2c00;
  classDef peer fill:#f0e6ff,stroke:#a78bfa,color:#2e1065;
  classDef orch fill:#e6f3ff,stroke:#6ea8fe,color:#002b55;
  classDef eval fill:#ffe6e6,stroke:#fb7185,color:#4c0519;
  classDef state fill:#f3f4f6,stroke:#9ca3af,color:#111827;
  classDef decision fill:#ffe6f0,stroke:#f472b6,color:#4a044e;

  Start([开始]) --> Setup[设置]
  Setup --> Workspace[(工作空间<br/>草稿 + 笔记)]

  Workspace --> Orch[编排器<br/>规划]
  Orch --> Fanout1{{并行：起草}}
  Fanout1 --> A1[代理 1]
  Fanout1 --> A2[代理 2]
  Fanout1 --> A3[代理 3]

  A1 --> Barrier1{{屏障 / 同步}}
  A2 --> Barrier1
  A3 --> Barrier1

  Barrier1 --> Write1[将草稿写入<br/>工作空间]
  Write1 --> Workspace

  Workspace --> Fanout2{{并行：同行完善}}
  Fanout2 --> PR1[同行 1<br/>利用他人内容完善]
  Fanout2 --> PR2[同行 2<br/>利用他人内容完善]
  Fanout2 --> PR3[同行 3<br/>利用他人内容完善]

  PR1 --> Barrier2{{屏障 / 同步}}
  PR2 --> Barrier2
  PR3 --> Barrier2

  Barrier2 --> Write2[将完善内容写入<br/>工作空间]
  Write2 --> Workspace

  Workspace --> OrchEval[编排器<br/>评估质量]
  OrchEval --> Stop{{完成？}}
  Stop -->|否：继续| Orch
  Stop -->|是| Final[最终<br/>综合]
  Final --> End([结束])

  class Fanout1,Fanout2,Barrier1,Barrier2 control;
  class A1,A2,A3 agent;
  class PR1,PR2,PR3 peer;
  class Orch orch;
  class OrchEval eval;
  class Workspace state;
  class Stop decision;
```

## 选择架构

| 架构 | 协调机制 | 迭代方式 | 何时使用 |
|---|---|---|---|
| **Independent（独立模式）** | 无 | 单次 | 需要多样化视角且不希望有交互开销时 |
| **Decentralized（去中心化模式）** | 点对点 | 固定轮次 | 代理应在没有中央权威的情况下自组织时 |
| **Centralized Iterative（集中迭代模式）** | 编排器驱动 | 质量门控 | 需要具有评估检查点的结构化分解任务时 |
| **Hybrid Iterative（混合迭代模式）** | 编排器 + 同行 | 质量门控 | 既需要自上而下的规划，又需要自下而上的同行完善时 |
