今天，[离线模式](/local/offline)管理着一个外部的 llama.cpp 服务器：Ante 安装它、启动它、监控它，并将其关闭。这种方式行之有效，也是目前支持的本地推理途径。下一步是一个在智能体进程**内部**运行的引擎。

:::warning
本页面描述的是一个发展方向，而不是一个已发布的功能。这里的任何内容都还不是发布的 Ante 构建版本的一部分。
:::

## 为什么选择进程内 {#why-in-process}

外部推理服务器一次只能看到一个 HTTP 请求。而嵌入在智能体运行时中的引擎可以看到整个智能体循环，这开启了任何通用服务器都无法做到的优化：

- **整个循环中的前缀复用。** 智能体的对话回合共享着长且稳定的前缀：系统提示词、工具定义、对话历史。了解回合生命周期的引擎可以使这些前缀常驻，而不是在每次请求时重新处理它们。
- **工具调用的约束解码。** 工具调用参数必须符合已知的模式。在这种语法下解码排除了格式错误的调用，而不是重试它们。
- **子智能体批处理。** 在同一模型上的并行子智能体可以通过一个引擎进行批处理，而不是在一个服务器端口上排队。

我们正在努力实现的结果：将本地模型作为智能体工作的首选基础，是基于其优点而被选择，而不仅仅是为了成本和隐私而容忍。与其他所有声明一样，这种说法将带着[你可以检查的数据](/benchmarks/eval)一起发布。

## 一个工作草图：nanochat-rs {#a-working-sketch-nanochat-rs}

[nanochat-rs](https://github.com/AntigmaLabs/nanochat-rs) 是我们针对这个基础设施的公开、实验性预览：一个纯 Rust 的微型 GPT 风格推理核心，构建在 [candle](https://github.com/huggingface/candle) 之上，集成了 Hugging Face，并拥有故意保持极简的表面。它在设计上是一个玩具 —— 这是对 [karpathy/nanochat](https://github.com/karpathy/nanochat) 的 Rust 重新实现，侧重于清晰度而不是性能 —— 但它展示了这种形态：与调用它的代码存在于同一进程中的原生推理，无需外部服务器二进制文件。

```bash
git clone https://github.com/AntigmaLabs/nanochat-rs
cd nanochat-rs
cargo run --release --features metal -- -p "写100个字"
```

## 现状 {#status}

今天运行本地模型的受支持方式是[离线模式](/local/offline)以及托管的 llama.cpp 引擎，或者是[你自己的引擎](/local/custom-engines)。进程内引擎的进展将会发布在[更新日志](/changelog)和 [Discord](https://discord.gg/pqhj3DNGz2) 上。
