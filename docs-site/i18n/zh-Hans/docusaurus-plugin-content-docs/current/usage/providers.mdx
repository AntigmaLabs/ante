Ante 具备跨提供商无关性。每个提供商均实现了统一的提示词发送与流式响应接口，在会话启动时根据目录解析提供商与模型。

本页介绍日常使用场景：选择提供商、完成认证以及自定义模型目录。关于内置提供商的完整列表、各模型参数以及 `catalog.json` 的完整规范，请参阅[目录参考手册](/reference/catalog-reference)。

## 选择提供商 {#selecting-a-provider}

可以通过三种方式指定提供商（优先级由高到低）：

1. **CLI 命令行参数** — `ante --provider anthropic --model claude-sonnet-5`
2. **配置文件** — 在 `~/.ante/settings.json` 中配置 `provider` 和 `model`
3. **自动检测** — 若均未指定，Ante 会自动选用已配置凭据的第一个提供商（若均未配置则回退到 `local` 本地模型）。

支持传入 `--provider` 的所有键名均在[目录参考手册](/reference/catalog-reference#built-in-providers)中列出。

在 TUI 会话进行中，输入 `/providers`：选择已连接的提供商，然后确认选择模型（与思考深度）。Ante 会自动记住每个提供商上次使用的模型。参见[模型选择、提供商与思考深度](/usage/models-and-thinking#switching-providers)。

## 身份认证 {#authentication}

大部分提供商直接从环境变量中读取 API 密钥：

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
ante --provider anthropic --model claude-sonnet-5
```

各提供商具体支持的认证方式（环境变量或 OAuth）可查阅[目录参考手册](/reference/catalog-reference#built-in-providers)。

### 粘贴 API 密钥 {#paste-an-api-key}

也可以在引导欢迎弹窗中直接粘贴密钥（随时可通过 `/welcome` 重新打开）：选择 **Use API key**，Ante 会根据密钥前缀自动识别提供商、掩码输入，并在通过提供商有效性校验后保存在 `~/.ante/auth/`（仅当前用户可读权限）。环境变量中配置的密钥优先级始终高于本地存储的密钥。

在配置 Anthropic 密钥步骤时，按 `Tab` 键可直接在浏览器中打开 Anthropic Console 进行授权 —— Ante 会自动为您预配 API 密钥，且密钥无需经过系统剪贴板。

### 订阅登录（OAuth） {#subscription-login-oauth}

支持订阅方案的提供商（Anthropic、OpenAI、Antix 等）可以通过 OAuth 授权直接登录，复用已有的订阅而无需管理 API 密钥。在 TUI 中输入 `/connect` 打开提供商登录向导。Ante 会自动拉起默认浏览器进行认证，完成后自动绑定当前会话。

<img src="/assets/cookbook/connect.gif" alt="通过 /connect 接入提供商" style={{width: '100%', borderRadius: '8px', margin: '16px 0'}} />

连接成功后，Ante 会为后续会话持久化保存凭证，无需每次重复登录。

:::tip
使用第三方提供商时，请确保所选模型支持工具调用（Function Calling）—— Ante 依赖该能力实现智能体闭环。如果效果不佳，建议切换为更大参数规模或能力更强的模型。
:::

## 自定义模型目录 {#custom-catalog}

创建 `~/.ante/catalog.json` 以添加 Ante 未内置的提供商、修改内置提供商属性或微调模型默认参数。该文件在启动时会合并覆盖到内置预设之上，因此只需声明新增或修改的部分。如果不想手写，可在 TUI 中运行 `/add-provider`：Ante 会发现端点提供的模型、探测每个模型接受的思考深度，并写入配置（重启后加载）。常见示例如下；完整 Schema 请查阅[目录参考手册](/reference/catalog-reference#catalogjson-schema)。

### 添加托管型提供商 {#add-a-hosted-provider}

大多数托管端点均兼容 OpenAI 协议。配置 `wire_style: "OpenAiCompatible"`，指定 `base_url` 并列出希望在选择器中展示的模型：

```json
{
  "providers": {
    "together": {
      "display_name": "Together AI",
      "base_url": "https://api.together.xyz/v1",
      "wire_style": "OpenAiCompatible",
      "auth": { "bearer": { "env_key": "TOGETHER_API_KEY" } },
      "preferred_models": [
        {
          "id": "moonshotai/Kimi-K2-Instruct",
          "description": "Kimi K2 on Together",
          "max_tokens": 16384,
          "context_limit": 128000,
          "effort": "medium"
        }
      ]
    }
  }
}
```

```bash
export TOGETHER_API_KEY="..."
ante --provider together --model moonshotai/Kimi-K2-Instruct
```

### 声明模型支持的思考深度 {#declare-supported-efforts}

[思考深度滑块](/usage/models-and-thinking#effort)的档位通常由提供商和模型家族内置推导，因此自定义端点上的模型可能得到不符合实际接口的档位。可使用 `supported_efforts` 声明真实集合；滑块将只显示这些级别，OpenAI 兼容提供商会把选择值作为同名的 `reasoning_effort` 发送：

```json
"preferred_models": [
  {
    "id": "kimi-k3",
    "effort": "high",
    "supported_efforts": ["low", "medium", "high"]
  }
]
```

空列表（`"supported_efforts": []`）表示该模型完全不接受思考深度设置。端点没有报告支持档位的标准 API；不确定时可让 `/add-provider` 自动探测。

### 添加无需认证的本地服务 {#add-a-local-provider-with-no-auth}

对于无需 API 密钥的本地服务可省略 `auth`，若提供商模型变动频繁（如 Ollama）也可省略 `preferred_models`。您仍可以通过 `--provider` 与 `--model` 显式调用任意模型 ID：

```json
{
  "providers": {
    "ollama": {
      "display_name": "Ollama",
      "base_url": "http://localhost:11434/v1",
      "wire_style": "OpenAiCompatible"
    }
  }
}
```

```bash
ante --provider ollama --model qwen2.5-coder:7b
```

### 覆盖内置提供商配置 {#patch-a-built-in-provider}

当配置中的 key 匹配内置提供商时，仅会修改指定的字段。将可选字段（如 `auth` 或 `http_headers`）设置为 `null` 可清除预设值：

```json
{
  "providers": {
    "openai": {
      "base_url": "http://localhost:8080/v1",
      "auth": null
    }
  }
}
```

### 传递额外自定义请求体参数 {#send-extra-request-parameters}

网关或自定义代理服务经常需要特定请求参数。将其配置在 `extra_body` 中，会自动合并到该提供商的所有 Chat 和 Streaming 请求体中：

```json
{
  "providers": {
    "my-gateway": {
      "display_name": "My Gateway",
      "base_url": "https://gateway.example.com/v1",
      "wire_style": "OpenAiCompatible",
      "auth": { "bearer": { "env_key": "MY_GATEWAY_API_KEY" } },
      "extra_body": {
        "service_tier": "priority"
      }
    }
  }
}
```

`extra_body` 只能追加新字段 —— Ante 为选定 wire style 生成的保留键（`model`、`messages`、`stream` 等）在启动时会被自动丢弃并打印提示，提供商仍会正常加载。参见[保留关键字列表](/reference/catalog-reference#extra-request-fields)。

### 覆盖模型默认参数 {#override-model-defaults}

在 `models` 部分可以按模型 ID 针对性调整参数而无需重新定义提供商：

```json
{
  "models": {
    "claude-opus-5": { "effort": "max" },
    "claude-sonnet-5": { "effort": "high", "max_tokens": 64000 },
    "gpt-5.5": { "temperature": 0.2 }
  }
}
```

## 第三方提供商接入 {#third-party-providers}

### 使用 Open Router {#using-open-router}

1. 在 [openrouter.ai](https://openrouter.ai/) 注册并生成 API 密钥。
2. 配置环境变量：
   ```bash
   export OPENROUTER_API_KEY="sk-or-..."
   ```
3. 调用 [Open Router 模型列表](https://openrouter.ai/models) 中的任意模型：
   ```bash
   ante --provider openrouter --model deepseek/deepseek-reasoner
   ```

### 兼容 OpenAI 格式的提供商 {#openai-compatible-providers}

许多提供商均提供 OpenAI 兼容的 API（如 Together AI、Fireworks、Groq Cloud、Perplexity 等）。临时调用时可直接利用内置的 `openai-compatible` 提供商而无需编辑 catalog 文件：

1. 设置基础 URL（该特定环境变量优先级高于 `MODEL_BASE_URL`）：
   ```bash
   export OPENAI_COMPATIBLE_BASE_URL="https://api.together.xyz/v1"
   ```
2. 设置 API 密钥：
   ```bash
   export OPENAI_COMPATIBLE_API_KEY="your-provider-api-key"
   ```
3. 启动调用：
   ```bash
   ante --provider openai-compatible --model meta-llama/Llama-3-70b-chat-hf
   ```
