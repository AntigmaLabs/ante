`ante-sdk` 是 Ante 的 Rust 客户端。你的程序发送 op、接收事件，而智能体循环、工具、审批与模型提供商都由 Ante 负责。SDK 处理 JSONL 分帧和宿主进程，你只需编写 harness，Ante 作为其核心。

该 crate 已发布在 [crates.io](https://crates.io/crates/ante-sdk)（API 文档见 [docs.rs](https://docs.rs/ante-sdk)），源码位于 [`crates/ante-sdk`](https://github.com/AntigmaLabs/ante/tree/main/crates/ante-sdk)。

```bash
cargo add ante-sdk
cargo add tokio --features macros,rt-multi-thread
```

## 最小客户端 {#a-minimal-client}

以下程序启动一个会话，发送一条提示词，并流式打印回复。需要 `PATH` 上有 `ante`；未设置的会话字段使用宿主在 `~/.ante/settings.json` 中的默认值。

```rust
use ante_sdk::{ConnectOptions, connect, protocol::{Evt, Op, SessionRequest}};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut client = connect("stdio".parse()?, ConnectOptions::default()).await?;

    client.send(Op::StartSession(SessionRequest {
        unattended: Some(true),
        ..Default::default()
    })).await?;
    client.send(Op::UserInput("explain what this project does".into())).await?;

    while let Some(msg) = client.next_event().await {
        match msg.event {
            Evt::MessageDelta(text) => print!("{text}"),
            Evt::TurnEnd { .. } | Evt::Error(_) => break,
            _ => {}
        }
    }
    client.close().await;
    Ok(())
}
```

`unattended: true` 会拒绝需要审批的调用，适合没有界面的程序。交互式客户端则应以 `ApprovalResponse` 或 `QuestionResponse` 响应 `TurnPause` 事件。

`Client::send` 返回该 op 被标记的 `Id`，所有响应该 op 的事件都以它作为 `parent`。`client.close()` 会发送 `Shutdown` 并等待宿主道别。

## 连接宿主 {#connecting-to-a-host}

`connect` 接收一个 `Endpoint`，它描述宿主在哪里可达。连接驱动哪个会话，由其上发送的 op（`StartSession`、`ResumeSession`）决定。

| Endpoint | 客户端行为 | 宿主生命周期 |
|---|---|---|
| `stdio` | 将 [`ante serve --stdio`](/usage/serve) 作为自身子进程拉起 | 随连接结束 |
| `unix:<path>` | 连接某个 `ante serve --sock` 宿主的套接字 | 长于该连接 |
| `ws://<addr>`, `wss://<addr>` | 连接 `ante serve --ws` 宿主，附带 `ConnectOptions::token` 作为 Bearer Token | 长于该连接 |

```rust
// 连接他人正在运行的宿主
let client = connect("unix:/tmp/ante.sock".parse()?, ConnectOptions::default()).await?;
```

原生 `ws://` 仅允许连接本地回环宿主。远程宿主必须使用 `wss://`（需启用可选的 `wss` 特性），确保 Token 不会以明文跨网络传输。

`ConnectOptions` 的所有字段均可选：`executable`（默认为 `PATH` 上的 `ante`）、追加在 `serve --stdio` 之后的 `args`、`cwd`、额外的 `env`，以及 `token`。`connect` 成功仅表示管道已打开或套接字已连上。协议没有握手问候，因此第一个 op 的回复才是存活性检查。

自身托管会话的进程可直接从其宿主获得同一 `Client` 类型，传递的也是相同的协议类型，因此客户端代码在两种场景下无需改动。

## 完整示例 {#worked-examples}

- [`examples/mini-tui`](https://github.com/AntigmaLabs/ante/tree/main/examples/mini-tui) 是单文件的聊天 TUI。它流式接收 `MessageDelta`，通过 `y`/`n` 响应 `TurnPause` 审批，并在按 Esc 时发送 `Interrupt`。在该目录下运行 `cargo run` 即可。
- [`examples/ante-gateway`](https://github.com/AntigmaLabs/ante/tree/main/examples/ante-gateway) 是 Slack 与 Discord 机器人，在共享宿主上为每个线程或私信分配独立会话。运行方式见[网关模式](/usage/gateway)。

## Op 与事件 {#ops-and-events}

SDK 以 `ante_sdk::protocol` 重新导出协议类型。[协议参考](/reference/protocol-reference)列出了全部 op 与事件，[`ante serve`](/usage/serve) 介绍宿主一侧：传输方式、套接字归属与各项限制。
