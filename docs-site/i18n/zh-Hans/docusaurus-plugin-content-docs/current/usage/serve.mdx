---
title: "ante serve"
description: "将 Ante 作为长期运行的服务器运行，用于编程式集成"
---

服务器模式将 Ante 作为长期运行的守护进程运行，外部客户端可以通过结构化的消息协议来驱动它。这非常适合构建编辑器集成、Web UI 或任何需要长期控制 Ante 的编程式工作流。

## 基本用法

```bash
ante serve
```

这将启动守护进程，并通过 stdin/stdout 桥接 [JSONL 协议](/reference/protocol-reference)。进程会保持存活，直到客户端发送 `Shutdown` 操作或关闭标准输入（stdin）。

### Stdio 传输（默认）

```bash
ante serve --stdio
```

`--stdio` 标志是可选的——stdio 是默认的传输方式。守护进程从标准输入（stdin）读取 `OpMsg` JSON 对象，并将 `EventMsg` JSON 对象写入标准输出（stdout），每行一个。

### WebSocket 传输

```bash
ante serve --ws 127.0.0.1:8080
```

`--ws` 标志在给定地址上启动一个 WebSocket 服务器。每个连接都会获得自己的守护进程实例。服务器会循环接受新连接，直到客户端发送 `Shutdown` 操作。

:::note
`--stdio` 和 `--ws` 是互斥的——你不能同时使用两者。
:::

## 工作原理

1. 守护进程启动并等待 stdin 上的操作
2. 发送 `StartSession` 操作，使用你选择的模型和提供商初始化一个会话
3. 发送 `UserInput` 操作以提交提示词
4. 在 stdout 上接收流式事件——思考增量、消息增量、工具调用、审批
5. 使用 `ApprovalResponse` 响应 `TurnPause` 事件，以批准或拒绝工具调用
6. 发送 `Shutdown`（或关闭 stdin）以优雅地停止守护进程

有关完整的消息目录和传输格式，请参阅[协议参考](/reference/protocol-reference)。

## 会话示例

```bash
# 启动守护进程，通过命名管道将 JSONL 发送到其 stdin
mkfifo /tmp/ante-pipe
ante serve < /tmp/ante-pipe &
echo '{"op":{"StartSession":{"model":"claude-sonnet-4-6","provider":"anthropic"}},"id":"op_001"}' > /tmp/ante-pipe
echo '{"op":{"UserInput":"what is 2+2"},"id":"op_002"}' > /tmp/ante-pipe
```

在实践中，你通常会生成该进程并直接写入其 stdin。这是一个极简的 Node.js 示例：

```javascript
const { spawn } = require("child_process");

const ante = spawn("ante", ["serve"]);
let buffer = "";

ante.stdout.on("data", (chunk) => {
  buffer += chunk.toString();
  const lines = buffer.split("\n");
  buffer = lines.pop();
  for (const line of lines) {
    if (!line.trim()) continue;
    const event = JSON.parse(line);
    console.log("Event:", event.event);
  }
});

ante.stdin.write(JSON.stringify({
  op: { StartSession: { model: "claude-sonnet-4-6", provider: "anthropic" } },
  id: "op_001"
}) + "\n");

ante.stdin.write(JSON.stringify({
  op: { UserInput: "explain what this project does" },
  id: "op_002"
}) + "\n");
```

## 与无头模式的区别

| | 无头模式 | 服务器模式 |
|---|---|---|
| **生命周期** | 单个提示词，然后退出 | 长期存活，多次交互 |
| **输入** | CLI 参数或 stdin 管道 | 结构化的 JSONL 操作 |
| **输出** | 格式化文本（极简/人类可读/JSON） | 原始协议事件 (JSONL) |
| **传输方式** | 不适用 | Stdio（默认）或 WebSocket (`--ws`) |
| **会话** | 隐式——每次调用一个 | 显式——客户端发送 `StartSession` |
| **工具审批** | 自动批准（隐含 Yolo 策略） | 客户端必须响应 `TurnPause` 事件 |

## CLI 参考

| 标志 | 描述 |
|---|---|
| `--stdio` | 在 stdin/stdout 上使用 JSONL（默认） |
| `--ws <ADDR>` | 通过 WebSocket 提供协议服务 |
| `--offline-model <PATH>` | 使用此 GGUF 模型启动本地 llama-server，并将其注册为每个连接客户端的 `local` 提供商 |

:::note
`--prompt` 标志不能与 `ante serve` 一起使用。请改用 `UserInput` 操作。
:::
