title: "ante serve"
description: "将 Ante 作为一个长生命周期的服务器运行，以进行编程式集成"
---

服务器模式（Server mode）将 Ante 作为一个长生命周期的守护进程运行，外部客户端可以通过结构化的消息协议来驱动它。这非常适合用于构建编辑器集成、Web UI，或者任何需要随时间控制 Ante 的编程式工作流。

## 基本用法 {#basic-usage}

```bash
ante serve
```

这会启动守护进程，并通过 stdin/stdout 桥接 [JSONL 协议](/reference/protocol-reference)。该进程将保持存活，直到客户端发送 `Shutdown` 操作或关闭 stdin。

### Stdio 传输（默认） {#stdio-transport-default}

```bash
ante serve --stdio
```

`--stdio` 标志是可选的 —— stdio 是默认的传输方式。守护进程从 stdin 读取 `OpMsg` JSON 对象，并将 `EventMsg` JSON 对象写入 stdout，每行一个。

### WebSocket 传输 {#websocket-transport}

```bash
ante serve --ws 127.0.0.1:8080
```

`--ws` 标志在给定地址上启动一个 WebSocket 服务器。每个连接都会获得其自己的守护进程实例。服务器循环接收新连接，直到客户端发送 `Shutdown` 操作。

:::note
`--stdio` 和 `--ws` 是互斥的 —— 您不能同时使用它们。
:::

## 它是如何工作的 {#how-it-works}

1. 守护进程启动并等待 stdin 上的操作
2. 发送一个 `StartSession` 操作，以使用您选择的模型和提供商初始化一个会话
3. 发送 `UserInput` 操作以提交提示词（prompts）
4. 在 stdout 上接收流式事件 —— 思考片段（thinking deltas）、消息片段（message deltas）、工具调用（tool calls）、审批请求（approvals）
5. 使用 `ApprovalResponse` 响应 `TurnPause` 事件，以批准或拒绝工具调用
6. 发送 `Shutdown`（或关闭 stdin）以优雅地停止守护进程

有关完整的消息目录和连线格式（wire format），请参阅[协议参考](/reference/protocol-reference)。

## 示例会话 {#example-session}

```bash
# 启动守护进程，通过命名管道将其标准输入（stdin）重定向为 JSONL
mkfifo /tmp/ante-pipe
ante serve < /tmp/ante-pipe &
echo '{"op":{"StartSession":{"model":"claude-sonnet-4-6","provider":"anthropic"}},"id":"op_001"}' > /tmp/ante-pipe
echo '{"op":{"UserInput":"what is 2+2"},"id":"op_002"}' > /tmp/ante-pipe
```

在实践中，您会生成进程并直接写入其 stdin。以下是一个极简的 Node.js 示例：

```javascript
const { spawn } = require("child_process");

const ante = spawn("ante", ["serve"]);
let buffer = "";

ante.stdout.on("data", (chunk) => {
  buffer += chunk.toString();
  const lines = buffer.split("\n");
  buffer = lines.pop();
  for (const line of lines) {
    if (!line.trim()) continue;
    const event = JSON.parse(line);
    console.log("Event:", event.event);
  }
});

ante.stdin.write(JSON.stringify({
  op: { StartSession: { model: "claude-sonnet-4-6", provider: "anthropic" } },
  id: "op_001"
}) + "\n");

ante.stdin.write(JSON.stringify({
  op: { UserInput: "explain what this project does" },
  id: "op_002"
}) + "\n");
```

## 与无头模式（headless mode）的区别 {#differences-from-headless-mode}

| | 无头模式 | 服务器模式 |
|---|---|---|
| **生命周期** | 单个提示词执行后即退出 | 长生命周期，多次交互 |
| **输入** | CLI 参数或 stdin 管道 | 结构化的 JSONL 操作 |
| **输出** | 格式化的文本 (minimal/human/json) | 原始协议事件 (JSONL) |
| **传输层** | 不适用 | Stdio（默认）或 WebSocket (`--ws`) |
| **会话** | 隐式 —— 每次调用一个 | 显式 —— 客户端发送 `StartSession` |
| **工具审批** | 自动批准（隐含 yolo 模式） | 客户端必须响应 `TurnPause` 事件 |

## CLI 参考 {#cli-reference}

| 标志 | 描述 |
|---|---|
| `--stdio` | 在 stdin/stdout 上使用 JSONL（默认） |
| `--ws <ADDR>` | 在 WebSocket 上提供协议服务 |
| `--offline-model <PATH>` | 使用此 GGUF 模型启动本地 llama-server，并将其注册为每个连接客户端的 `local` 提供商 |

:::note
`--prompt` 标志不能与 `ante serve` 一起使用。请改用 `UserInput` 操作。
:::
