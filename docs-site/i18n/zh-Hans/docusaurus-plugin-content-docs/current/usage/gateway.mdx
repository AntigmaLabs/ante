---
title: "网关模式"
description: "将 Ante 作为一个机器人在 Slack 或 Discord 中运行"
---

网关模式（Gateway mode）将 Ante 作为长生命周期的机器人运行，可从 Slack、Discord 访问，或者同时从两者访问。每个对话 —— 频道线程或直接消息（DM） —— 都会获得自己独立的智能体（agent）会话，因此多个用户和团队可以并行地与 Ante 对话而不会交叉状态。

## 基本用法 {#basic-usage}

```bash
ante gateway
```

这将读取 `~/.ante/channels.json`，连接到您启用的每个平台，并开始监听消息。

## 配置 {#configuration}

创建 `~/.ante/channels.json`。您可以仅启用 Slack、仅启用 Discord，或同时启用两者。

```json
{
  "slack": {
    "enabled": true,
    "bot_token": "env:SLACK_BOT_TOKEN",
    "app_token": "env:SLACK_APP_TOKEN",
    "allow_from": "open"
  },
  "discord": {
    "enabled": true,
    "bot_token": "env:DISCORD_BOT_TOKEN",
    "allow_from": ["123456789012345678"]
  }
}
```

以 `env:` 开头的值在启动时从环境中读取，因此令牌（tokens）被保存在文件之外。

### 访问控制 {#access-control}

`allow_from` 字段决定机器人将响应谁：

| 值 | 谁可以与机器人对话 |
| --- | --- |
| `"open"` | 工作区 / 服务器上的任何人 |
| `["U123", "U456"]` | 仅列出的用户 ID |
| *(省略)* | 拒绝所有（安全的默认设置） |

## 设置 Slack {#setting-up-slack}

1. 在 [api.slack.com/apps](https://api.slack.com/apps) 创建一个应用 → **From scratch**。
2. **Settings → Socket Mode**：启用它并创建一个具有 `connections:write` 的 App 级别令牌。复制 `xapp-…` 令牌 —— 这是您的 `app_token`。
3. **Features → OAuth & Permissions → Bot Token Scopes**：添加 `chat:write`、`app_mentions:read`、`channels:history`、`im:history`、`im:write`。
4. **Features → Event Subscriptions**：启用事件（events）并订阅 `message.channels` 和 `message.im`。
5. **Features → App Home**：启用 Messages Tab 并允许用户在那里发送消息。
6. **Settings → OAuth & Permissions → Install to Workspace**。复制 `xoxb-…` Bot User OAuth Token —— 这是您的 `bot_token`。
7. 在您希望机器人进入的每个频道中：`/invite @your-bot-name`。

```bash
export SLACK_BOT_TOKEN="xoxb-..."
export SLACK_APP_TOKEN="xapp-..."
```

**在 Slack 中使用机器人：** 在频道中 `@mention` 提及它，或直接发私信（DM）给它。回复总是以线程的形式出现。

:::note
每当您更改作用域或事件订阅时，必须**重新安装到工作区（Reinstall to Workspace）**才能生效。
:::

## 设置 Discord {#setting-up-discord}

1. 在 [discord.com/developers/applications](https://discord.com/developers/applications) 创建一个应用程序 → **New Application**。
2. **Bot**：复制令牌 —— 这是您的 `bot_token`。在 **Privileged Gateway Intents** 下，启用 **Message Content Intent**（必需）。
3. **OAuth2 → URL Generator**：在 **Scopes** 下勾选 `bot`；在 **Bot Permissions** 下勾选 `Send Messages`、`Read Message History`、`View Channels`。打开生成的 URL 以将机器人邀请到您的服务器。

```bash
export DISCORD_BOT_TOKEN="..."
```

**在 Discord 中使用机器人：** 在服务器频道中 `@mention` 提及它，或直接发送私信。机器人将以引用您消息的形式回复 —— 回复机器人的消息以继续对话。

## 与机器人对话 {#talking-to-the-bot}

一旦机器人进入您的工作区或服务器并且网关（gateway）正在运行，您就可以像与其他任何机器人一样与它聊天。几个特定的回复有特殊含义。

您可以随时通过发送以下内容中断机器人：

| 命令 | 效果 |
| --- | --- |
| `stop` | 取消当前任务（类似于在 TUI 中的 Ctrl+C） |

当机器人请求权限运行工具时，使用以下内容之一进行回复：

| 回复 | 效果 |
| --- | --- |
| `yes`（或 `y`） | 批准此工具调用 |
| `no`（或 `n`） | 跳过此工具调用 |
| `always` | 批准并在此会话的剩余时间内允许使用此工具 |

有关工具审批流程的更多信息，请参见[批准](/usage/approvals)。

## CLI 参考 {#cli-reference}

```bash
ante gateway [--config PATH] [--model MODEL] [--provider PROVIDER] [--output-format FORMAT] [--offline-model PATH]
```

| 标志 | 默认值 | 描述 |
| --- | --- | --- |
| `--config` | `~/.ante/channels.json` | channels 配置文件的路径 |
| `--model` | `local` | 供每个会话使用的 LLM 模型 |
| `--provider` | `local` | 所选模型的提供商 |
| `--output-format` | `minimal` | Gateway 的 stdout 输出格式：`minimal`、`human` 或 `json` |
| `--offline-model` | — | 本地 GGUF 文件的路径。在接受消息之前启动一个共享的 llama-server，并将每个对话路由通过它（强制使用 `--provider local --model local`） |

:::tip
默认设置假定使用本地 llama-server。要使用托管提供商，请显式传递 `--provider` 和 `--model`（例如，`ante gateway --provider anthropic --model claude-sonnet-4-6`）。
:::

### 输出格式 {#output-formats}

| 格式 | 显示内容 |
| --- | --- |
| `minimal` | 仅智能体消息、信息和错误 |
| `human` | 所有带彩色格式的事件（用于调试） |
| `json` | 所有事件都采用 JSON 行格式（用于通过管道传输给另一个工具） |

## 故障排除 {#troubleshooting}

**Slack："Sending messages to this app has been turned off"**
在 **App Home** 下启用 Messages Tab 并允许用户从中发送消息，然后重新安装到工作区（Reinstall to Workspace）。

**Slack：机器人在频道中不对 `@mentions` 作出反应**
确保已将机器人邀请到该频道（`/invite @bot-name`），并且在您的 Event Subscriptions 中启用了 `message.channels`。更改事件或作用域后请重新安装。

**Discord：机器人没有反应**
确认在机器人上启用了 **Message Content Intent**，并且它在该频道中拥有 `Send Messages` 和 `Read Message History` 的权限。

**Gateway 在收到消息后未显示任何输出**
使用 `--output-format human` 运行以查看每一个事件，并检查 `~/.ante/logs/` 中的错误详情。
