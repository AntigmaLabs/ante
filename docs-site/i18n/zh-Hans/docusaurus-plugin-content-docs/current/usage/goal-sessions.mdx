# 目标导向型会话（Goal-Driven Sessions）

当面对超出单次提示词即可完成的复杂研发任务时，使用 `/goal` 命令。设定一个具体的成功条件，Ante 将持续自主推进会话，直到该条件完全达成：

```text
/goal 所有单元测试均通过且文档构建成功无死链
```

## 闭环运作机制

Ante 开始或持续推进任务，并在每一轮 Turn 完成后评估当前进展。如果目标尚未达成，它会自动发起携带评估器反馈的下一轮 Turn，智能体继续进行修正和推进。

循环在以下情况下停止：

- **达成（Met）** — 评估器判定成功条件已完全满足
- **不可达（Unreachable）** — 评估器判定在当前上下文和约束下无法达成
- **手动清除（Cleared）** — 您执行了 `/goal clear` 命令
- **手动中断（Interrupted）** — 您在轮次执行中手动中止了智能体

内置的最大迭代轮次上限也会终止循环，防止会话失控。

## 管理目标

| 指令 | 效果 |
|---|---|
| `/goal <条件>` | 设定（或替换）当前活跃的目标条件 |
| `/goal` | 查看当前目标的执行状态与评估进展 |
| `/goal clear` | 清除目标并退出自主迭代循环 |

## 编写高质量的验收条件

评估器的准确度取决于给出的成功条件是否具体。尽量使用**具体且可客观检验**的描述：

- `所有单元测试通过，且 cargo clippy 报告 0 警告` 远优于 `优化代码`
- `文档站点成功构建且没有损坏的链接` 远优于 `修复文档`
- `基准测试脚本报告 p95 延迟低于 200ms` 远优于 `让程序更快`

模糊的条件会迫使评估器进行猜测，可能导致循环过早停止或无法收敛。

## 无人值守自动化运行

当您离开终端时，目标会话能发挥最大价值。运行前建议提前配置两项：

- [授权机制](/usage/approvals) — 提前配置好智能体所需的工具执行白名单（例如 Auto 或 Yolo 模式），否则循环在遇到首次未授权命令时会暂停等待人工输入。
- [会话恢复](/usage/tui#session-resume) — 所有会话均持久化保存在磁盘上，即使关闭终端，也可以随时通过 `/resume` 重新接管并继续任务。

## 编程方式调用

目标循环是 Ante 通信协议的原生组成部分：`Op::Goal` 支持设置、清除和查询状态，[Server 服务模式](/usage/serve) 下的外部客户端可以与 TUI 一样以编程方式驱动目标循环。
