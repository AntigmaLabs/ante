# 目标驱动的会话 {#goal-driven-sessions}

当工作不仅仅需要一次提示词就能完成时，使用 `/goal`。设定一个成功条件，Ante 会持续驱动会话，直到该条件得到满足：

```text
/goal all tests pass and the docs build succeeds
```

## 循环如何工作 {#how-the-loop-works}

Ante 开始或继续朝着该条件努力，然后在每个轮次（turn）结束后评估对话。如果目标没有达成，它会发送一个携带评估器反馈的延续轮次，并且智能体会继续工作。

当目标处于以下状态时，循环停止：

- **已满足（Met）** —— 评估器判定条件已达成
- **无法达成（Unreachable）** —— 评估器判定条件无法满足
- **已清除（Cleared）** —— 您运行了 `/goal clear`
- **被中断（Interrupted）** —— 您在轮次中间停止了智能体

内置的迭代上限也会结束循环，以此作为防止失控会话的最后防线。

## 管理目标 {#managing-the-goal}

| 命令 | 效果 |
|---|---|
| `/goal <condition>` | 设置（或替换）活动目标 |
| `/goal` | 显示当前的目标状态 |
| `/goal clear` | 清除目标并停止循环 |

## 编写良好的条件 {#writing-good-conditions}

评估器的敏锐程度取决于您给它的条件。使其变得具体且可检查：

- `all tests pass and cargo clippy reports no warnings` 胜过 `improve the code`
- `the docs build succeeds with no broken links` 胜过 `fix the docs`
- `the benchmark script reports p95 latency under 200ms` 胜过 `make it faster`

模糊的条件迫使评估器去猜测，这意味着循环可能会过早停止，或者在不收敛的情况下无效运转。

## 无人值守运行 {#running-unattended}

目标会话在您离开时大放异彩。在这之前需要设置两件事：

- [审批](/usage/approvals) —— 预先批准智能体将需要的命令，否则循环会在第一个提示处停滞不前，等待您的操作。
- [会话恢复](/usage/tui#session-resume) —— 每个会话都会持久化到磁盘，因此如果您关闭终端，`/resume` 可以重新拾起工作。

## 编程式使用 {#programmatic-use}

目标循环是 Ante 的连线协议（wire protocol）的一部分：`Op::Goal` 携带有设置、清除和状态命令，因此[服务器模式（server-mode）](/usage/serve)的客户端可以像 TUI 一样驱动它们。
