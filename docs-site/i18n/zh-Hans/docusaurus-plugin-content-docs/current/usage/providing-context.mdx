# 提供上下文：文件、目录与网络检索

为智能体提供精准的上下文信息：在提示词中直接引用本地文件和目录，或让 Ante 自动从互联网获取所需内容。

## 使用 @ 语法引用文件 {#using--mentions}

在输入框中输入 `@` 紧接着输入文件或目录路径。Ante 会在您输入时实时弹出搜索下拉列表 —— 按 Tab 键补全，按 Enter 键确认。

<img src="/assets/cookbook/files.gif" alt="使用 @ 语法添加文件上下文" className="cookbook-demo" />

- **`@path/to/file.rs`** — 将该文件的完整内容嵌入到当前消息中
- **`@path/to/dir/`** — 嵌入该目录的树状结构列表

补全会搜索完整项目树，包括嵌套超过六层的文件，并遵循与 Ante 文件工具相同的忽略规则。项目相对搜索会复用后台构建的索引进行快速模糊匹配；`~/`、绝对路径、`../` 和 `./` 路径同样可用，因此仍可引用项目之外的文件。

这确保了智能体能够直接精准查阅您关注的代码，避免猜测或盲目搜索。

:::tip
如果直接粘贴多个文件路径，Ante 会自动为其添加 `@` 前缀。单次提示词中可以引用任意数量的文件。
:::

## 图片与 PDF 附件 {#images-and-pdfs}

在输入框中按 `Ctrl+V` 或 `Ctrl+Shift+V` 可粘贴剪贴板图片；终端需要将该快捷键传给 Ante。使用 OpenAI Responses 格式的提供商时，用户图片与 PDF 附件会保留在发送的请求中。图片输入仍取决于模型的 [`support_vision`](/reference/catalog-reference#model-fields) 能力；纯文本模型的请求会过滤图片，但不改变保存的对话。

在 OpenAI Responses 和兼容 OpenAI 的 Chat Completions 接口上，工具返回的图片及受支持文件会保留与原始工具调用的关联，即使多个工具同时运行也能区分来源。

若端点限制每次请求的图片数量，可为提供商设置 [`max_request_images`](/reference/catalog-reference#request-image-limits)。Ante 在发送的请求中保留最新图片，并将较早图片替换为文本标记，已保存的历史不变。PDF 不计入此上限。

## 检索并获取网络内容 {#pulling-in-web-content}

Ante 可以搜索网络并抓取指定 URL 的内容，让您无需离开终端即可查阅文档、查询 API 或调研技术主题。只需自然提问，Ante 将自动调用网络浏览工具获取信息：

<img src="/assets/cookbook/webbrowse.gif" alt="Ante 执行网络检索" className="cookbook-demo" />

智能体可以：

- **搜索互联网** 获取文档、代码示例和解决方案
- **抓取指定 URL** 直接阅读其内容（如 API 文档、发布说明、技术博客）
- **总结提炼** 内容并将其整合至当前对话上下文中

当您使用不熟悉的第三方库或需要查阅工具/API 的最新文档时，这尤其有效。

:::note
使用 `WebFetch` 可读取已知 URL。要查找来源，可让 Ante 使用 `WebSearch`。支持搜索的 Anthropic、OpenAI、Gemini、Grok、OpenRouter、Antix 和 DeepSeek 配置会自动启用搜索。DeepSeek 直接使用当前会话的凭据。详见[工具参考](/reference/tools-reference#websearch)。
:::

:::tip
也可以在命令行中直接通过管道将网页内容传入 Ante：`curl https://example.com/docs | ante -p "summarize this"`。
:::
