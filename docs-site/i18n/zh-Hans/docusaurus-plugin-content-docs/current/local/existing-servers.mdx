---
title: 已有服务器
description: "将 Ante 的离线模式附加到您正在运行的 llama.cpp 服务器上"
---

当您已经自行运行了 `llama-server` 时可以使用已有服务器：比如通过 Docker 运行、自定义的 llama.cpp 构建版本、局域网中的另一台机器，或是使用了 Ante 未直接管理的具有特殊启动标志（flags）的派生版本（fork）。

Ante 仍然将此端点（endpoint）视为 `local` 提供商，因此，就像使用内置的托管离线模型一样，正常的智能体循环、模型切换以及提供商行为均能正常工作。Ante 不拥有从外部附加进来的服务器的所有权，且绝对不会为您停止它们。

## 自动检测本地服务器 {#auto-detect-localhost-servers}

打开 TUI 并运行：

```bash
/offline-mode
```

Ante 会在 **8080-8179** 端口扫描兼容 llama.cpp 的服务器。它会检查 `/health`，从 `/v1/models` 读取模型名称，并将检测到的服务器列在本地模型（local）与已验证模型（verified models）的上方。

即使尚未安装 Ante 固定版本的 llama.cpp 引擎，此扫描依然会执行。若检测到运行中的服务器，请选择它并按下 `Enter` 键进行附加连接。

## 手动附加连接 {#attach-manually}

在 `/offline-mode` 下，按下 `Ctrl+A` 然后输入端点信息：

```text
127.0.0.1:8080
```

仅填写端口表示使用 `127.0.0.1`：

```text
8080
```

也接受主机名：

```text
llama-box.local:8080
```

此对话框暂不支持输入带方括号的 IPv6 端点。当 Ante 探测 `/health` 和 `/v1/models` 之后，如果有任何连接失败的情况都会显示在离线模式对话框中。

## Docker 示例 {#docker-example}

这会启动官方的 llama.cpp 服务器镜像，并将其在端口 `8080` 暴露给 Ante：

```bash
docker run --rm \
  -p 8080:8080 \
  -v "$PWD/models:/models" \
  ghcr.io/ggml-org/llama.cpp:server \
  --model /models/model.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --ctx-size 32768 \
  --jinja
```

对于 CUDA 构建，请使用相匹配的 llama.cpp 镜像（如 `ghcr.io/ggml-org/llama.cpp:server-cuda`），并为您机器添加相关的 Docker GPU 运行时标志。

## 停止连接行为 (Detach behavior) {#detach-behavior}

当 Ante 启动 `llama-server` 时，它拥有该进程的控制权并能停止它。而当 Ante 附加到一个外部服务器时，停止离线模式仅会断开 Ante 与该端点的连接，并恢复原有的静态 `local` 提供商条目。外部服务器将继续保持运行。

附加到非回环（non-loopback）主机上意味着您会将对话数据发送至该主机。请确保您只连接到您亲自操作或信任的远程端点。

## 相关的环境变量 {#related-environment-variables}

`ANTE_LOCAL_PROVIDER_PORT` 用于更改在没有活跃的离线模式服务器会话时，静态 `local` 提供商预设所使用的端口：

```bash
ANTE_LOCAL_PROVIDER_PORT=8081 ante --provider local "您的提示词"
```

只要处于附加连接状态，手动附加连接或自动检测到的正在运行的服务器均会覆盖这一静态提供商的设置。

`ANTE_OFFLINE_CONTEXT` 会在 Ante 启动托管离线模型时修改默认的上下文窗口上限。它不会改变由您在外部启动的服务器配置。
