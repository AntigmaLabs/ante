---
title: 更新与通道
description: "保持 Ante 为最新版本，并选择适合你的发布通道"
---

Ante 作为一个单文件二进制程序发布，并支持就地（In-place）自更新 —— 首次安装时运行的 `install.sh` 脚本将被 `ante update` 再次调用，并从当前二进制文件跟踪的更新通道中拉取内容。

## 更新

检查当前通道上是否有新的 Ante 版本，如果有则进行安装：

```bash
ante update
```

如果存在更新的版本，Ante 将运行对应通道的安装程序，并在安装就绪后打印新版本信息。重启 Ante 即可开始使用。

如果你已经在使用最新版本，Ante 会打印一条确认信息并退出，不对二进制文件做任何修改。

## 锁定版本或回滚

使用 `--version` 锁定安装特定版本：

```bash
ante update --version v0.preview.33
ante update --version 0.preview.33
```

该命令会绕过通道中“检查新版本”的逻辑，因此它可用于升级、重新安装当前版本，或回滚到较早的已发布版本。回滚时，Ante 会记住你放弃的那个较新版本，这样下一次的后台更新提示就不会立即要求你重新安装它。

## 更新通道 (Channels)

更新通道是命名的构建轨道。Ante 提供了两个通道：

| 通道 | 描述 |
|---|---|
| `stable` | 推荐日常使用。通过发布工作流生成的正式 Tag 稳定版本。 |
| `nightly` | 基于开发分支构建。新功能和缺陷修复会最先在这里发布。 |

默认通道为 `stable`。二进制文件跟踪的通道存储在 `~/.ante/settings.json` 的 `channel` 字段中 —— `ante update` 每次运行时都会读取此配置，应用内的更新提示同样使用该设置。

```json
{
  "channel": "nightly"
}
```

若将 `channel` 设置为空字符串或省略该字段，将默认回退至 `stable`。

`latest` 是一个已废弃的通道名称。现存仍使用 `latest` 的设置或命令将被视同为 `stable`。

## 切换通道

你可以将通道名称作为位置参数，或通过 `--channel` 选项传递：

```bash
# 位置参数形式
ante update nightly

# 选项形式
ante update --channel nightly
```

这两种方式都会拉取指定通道的清单，并执行安装程序。此类通道覆盖仅在当次更新生效 —— 若要永久生效，让未来的 `ante update` 都遵循新的通道，请编辑 `~/.ante/settings.json` 并设置 `"channel": "nightly"`。

通道名称只能包含 ASCII 字母、数字、`.`、`_` 或 `-`。

## 首次安装

安装脚本同样支持指定通道名称。若要在全新环境中安装非默认通道的版本：

```bash
curl -fsSL https://ante.run/install.sh | bash -s -- nightly
```

若不加参数，安装脚本默认使用 `stable` 通道。

默认情况下，安装脚本将二进制文件写入 `~/.ante/bin`。你可以通过设置 `ANTE_INSTALL_DIR` 变量，将文件安装到已经包含在系统 `PATH` 中的任意目录：

```bash
curl -fsSL https://ante.run/install.sh | ANTE_INSTALL_DIR=/usr/local/bin bash
```

## 更新检查机制

启动时，Ante 最多每六小时在后台检查一次通道更新，并将结果缓存在 `~/.ante/versions.json` 中。如果发现新版本，TUI 会弹出更新提示并展示发布说明；如果你忽略了某个版本，在下一个更新发布前它都不会再次提示。手动运行 `ante update` 时会忽略缓存，始终拉取最新清单。
