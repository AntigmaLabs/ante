---
title: 提供商
description: "选择并配置您的模型提供商"
---

Ante 与提供商无关。每个提供商实现了一个通用的接口，用于发送提示和接收流式响应，而提供商和模型则在会话启动时从目录中解析。

本页涵盖日常任务：选择提供商、身份验证以及自定义目录。如需了解完整的内置提供商列表、它们提供的每个模型，以及完整的 `catalog.json` 架构，请参阅 [目录参考](/reference/catalog-reference)。

## 选择提供商

您可以通过三种方式设置您的提供商，优先级从高到低：

1. **CLI 标志** — `ante --provider anthropic --model claude-sonnet-4-6`
2. **设置文件** — 在 `~/.ante/settings.json` 中设置 `provider` 和 `model`
3. **自动检测** — 如果您都不指定，Ante 将使用您拥有凭证的第一个提供商（如果没有，则使用 `local`）。

您可以传递给 `--provider` 的每一个提供商 ID，都列在 [目录参考](/reference/catalog-reference#built-in-providers) 中。

## 身份验证

大多数提供商从环境变量中读取 API 密钥；Anthropic、OpenAI 和 Antix 也可以在 TUI 中通过 OAuth 以交互方式进行登录。

```bash
# API 密钥
export ANTHROPIC_API_KEY="sk-ant-..."
ante --provider anthropic --model claude-sonnet-4-6
```

每个提供商的确切身份验证方法（环境变量名或 OAuth）都在 [目录参考](/reference/catalog-reference#built-in-providers) 中。

:::tip
使用第三方提供商时，请确保模型支持工具调用（Function Calling） — Ante 依赖它来实现代理能力。如果结果不佳，请尝试使用更大或功能更强的模型。
:::

## 自定义目录 {#custom-catalog}

创建 `~/.ante/catalog.json` 以添加 Ante 尚未自带的提供商、修补内置提供商或调整模型的默认设置。在启动时，它会被合并到内置预设之上，因此您只需指定您想要添加或更改的内容。以下示例为常见情况；请参阅 [目录参考](/reference/catalog-reference#catalogjson-schema) 了解完整的架构、身份验证形式和解析规则。

### 添加托管提供商

大多数托管端点都兼容 OpenAI。以 `wire_style: "OpenAiCompatible"` 注册一个，将 `base_url` 指向它，并列出您希望在选择器中显示的模型：

```json
{
  "providers": {
    "together": {
      "id": "together",
      "display_name": "Together AI",
      "base_url": "https://api.together.xyz/v1",
      "wire_style": "OpenAiCompatible",
      "auth": { "bearer": { "env_key": "TOGETHER_API_KEY" } },
      "preferred_models": [
        {
          "id": "moonshotai/Kimi-K2-Instruct",
          "description": "Kimi K2 on Together",
          "max_tokens": 16384,
          "context_limit": 128000,
          "thinking": "Enabled"
        }
      ]
    }
  }
}
```

```bash
export TOGETHER_API_KEY="..."
ante --provider together --model moonshotai/Kimi-K2-Instruct
```

### 添加无身份验证的本地提供商

对于不需要密钥的提供商可以省略 `auth`；当提供商没有稳定的选择器或默认模型列表时可以不写 `preferred_models` —— 这对本地服务器（如 Ollama）非常方便，因为可用的模型会随着您的拉取而改变。您仍然可以通过 `--provider` 和 `--model` 显式传递任何模型 ID：

```json
{
  "providers": {
    "ollama": {
      "id": "ollama",
      "display_name": "Ollama",
      "base_url": "http://localhost:11434/v1",
      "wire_style": "OpenAiCompatible"
    }
  }
}
```

```bash
ante --provider ollama --model qwen2.5-coder:7b
```

### 修补内置提供商

当键值与内置提供商匹配时，仅会更改您设置的字段。
将诸如 `auth` 或 `http_headers` 等可选字段设置为 `null` 即可清除预设值：

```json
{
  "providers": {
    "openai": {
      "base_url": "http://localhost:8080/v1",
      "auth": null
    }
  }
}
```

### 覆盖模型默认设置

`models` 部分通过 ID 对模型进行修补，而无需重新定义它。您设置的每个字段都会替换内置的默认值；其余各项保持原样：

```json
{
  "models": {
    "claude-opus-4-8": { "thinking": "Max" },
    "claude-sonnet-4-6": { "thinking": "Deep", "max_tokens": 64000 },
    "gpt-5.5": { "temperature": 0.2 }
  }
}
```

## 第三方提供商

### 使用 Open Router

1. 在 [openrouter.ai](https://openrouter.ai/) 注册并生成一个 API 密钥。
2. 设置您的 API 密钥：
   ```bash
   export OPENROUTER_API_KEY="sk-or-..."
   ```
3. 使用来自 [Open Router 的模型列表](https://openrouter.ai/models) 的任何模型：
   ```bash
   ante --provider openrouter --model deepseek/deepseek-reasoner
   ```

### 兼容 OpenAI 的提供商

许多 LLM 提供商暴露了兼容 OpenAI 的 API（例如 Together AI、Fireworks、Groq Cloud、Perplexity）。作为一次性使用，您可以通过环境变量复用内置的 `openai-compatible` 提供商（无需编辑目录）：

1. 设置基础 URL — 每个提供商特定的变量优先于 `MODEL_BASE_URL`：
   ```bash
   export OPENAI_COMPATIBLE_BASE_URL="https://api.together.xyz/v1"
   ```
2. 设置您的 API 密钥：
   ```bash
   export OPENAI_COMPATIBLE_API_KEY="your-provider-api-key"
   ```
3. 使用兼容 OpenAI 的提供商运行：
   ```bash
   ante --provider openai-compatible --model meta-llama/Llama-3-70b-chat-hf
   ```

对于您将重复使用的内容，建议将具名提供商添加到您的 [自定义目录](#custom-catalog) 中，以便它出现在选择器中。
