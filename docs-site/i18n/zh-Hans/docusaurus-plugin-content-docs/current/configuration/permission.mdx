Ante 拥有一个权限系统，可控制工具调用是自动批准、需要用户确认还是被完全拒绝。

## 权限模式 {#permission-modes}

| 模式 | 行为 |
|---|---|
| `strict` | 首先遵守规则。如果没有匹配的规则，则允许使用已知安全的只读 Bash 命令，而其他所有命令都会询问。这是默认设置。 |
| `auto` | 首先遵守规则。如果没有匹配的规则，则允许工具调用，除非 Bash 检测到危险命令，此时会询问。 |
| `yolo` | 所有工具调用都会自动获得批准 — 没有提示，不进行规则评估，包括 `deny` 规则。 |

在 `~/.ante/settings.json` 中设置模式：

```json
{
  "permission_mode": "auto",
  "permissions": {
    "allow": ["Bash(npm run *)"],
    "ask": ["Write"],
    "deny": ["Bash(rm *)"]
  }
}
```

或者在每个会话中进行覆盖：

```bash
ante --yolo "run cargo clippy and fix all warnings"
ante --permission-mode auto "update docs and run tests"
```

在 TUI 中，按 **Shift+Tab** 可以实时循环切换模式：`strict` → `auto` → `yolo` → `strict`。更改适用于下一个回合，而不会干扰正在进行的回合。

:::warning
在无头模式下，隐含 `yolo` 模式 — 所有工具都会自动获得批准，因为没有交互式提示。
:::

## 决策 {#decisions}

| 决策 | 效果 |
|---|---|
| **Allow（允许）** | 工具立即执行，没有提示 |
| **Ask（询问）** | 提示用户批准或拒绝 |
| **Deny（拒绝）** | 工具调用被阻止 |

## 规则 {#rules}

权限规则将**决策**与**工具匹配器**配对。持久规则位于 `~/.ante/settings.json` 的 `permissions.allow`、`permissions.ask` 和 `permissions.deny` 下。

优先级是固定的：**deny > session grants > ask > allow > tool defaults**。在每个桶内，匹配器是一个无序集合。会话授权（session grants）是当您批准“针对此会话”的调用时添加的临时允许（参见 [会话授权](#session-grants)）。

```
规则：  deny=[Bash(rm *)], ask=[Bash], allow=[Write]
                ↓
工具调用：Bash({ "command": "ls" })
                ↓
匹配：Ask(Bash)
                ↓
结果：Ask (提示用户)
```

如果没有匹配的规则，则由模式决定后备方案：`strict` 会询问，除非是已知安全的只读 Bash 命令；`auto` 会允许，除非是危险的 Bash 命令；`yolo` 立即允许。

### 默认规则 {#default-rules}

| 工具 | 默认决策 |
|---|---|
| `Bash` | Ask |
| `Write` | Ask |
| `Edit` | Ask |
| `Read` | Allow |
| `Glob` | Allow |
| `Grep` | Allow |
| `Agent` | Allow |
| `TodoWrite` | Allow |
| `WebFetch` | Ask |
| `WebSearch` | Ask |
| `Browser` | Ask |
| `PTY` | Allow |
| `ViewImage` | Allow |

在 `strict` 模式下，检查完明确的规则后，只读 shell 命令也可以作为最终的后备方案被自动批准。这涵盖了经过审查的只读程序 — 以及仅由它们构建的管道或 `&&` / `||` / `;` 序列；任何带有重定向、命令替换或无法识别的命令的调用仍会提示。

在 `auto` 模式下，对于未匹配的调用，证明责任会反转：非 Bash 工具会运行，Bash 也会运行，除非危险命令分类器将其标记为需要批准。

### 会话授权 {#session-grants}

在审批提示中，您可以通过三种方式批准调用：

- **Yes** — 仅批准这一次调用。
- **Yes, allow … for this session** — 为剩余的运行过程添加临时授权。它覆盖 `ask`/`allow` 规则和工具默认值，但从不覆盖 `deny`，并在会话结束时消失。
- **Yes, always allow … (save to settings)** — 将匹配器追加到 `~/.ante/settings.json` 中的 `permissions.allow` 中，使其在未来的会话中也适用。

该授权是有作用域的，而不是一刀切的。单个批准的 Bash 命令概括为一个**双标识符前缀**，因此下一个类似的调用不会重新提示 — 批准 `cargo test -p foo` 会授予 `Bash(cargo test *)`。被危险分类器标记的命令（例如 `rm -rf build`）、其第二个标识符是标志的命令（`ls -la`）以及多阶段序列（`git add -A && git commit -m wip`）停留在**精确命令**的作用域，而不是扩大范围。`Agent`、`Read` 和 `Edit` 的作用域限定为其主要参数（子智能体类型或文件路径）；没有已知主要参数的工具按名称进行授权。

授权具备包容性感知：如果较窄的授权已被较宽的授权覆盖，则会放弃较窄的授权；批准较宽的授权将吸收多余的较窄授权 — 因此重复批准 `cargo test …` 调用将折叠成一个单一的 `Bash(cargo test *)` 规则，而不是堆积起来。

## 工具匹配器 {#tool-matchers}

### 简单匹配器 {#simple-matcher}

按名称匹配工具的**任何**调用：

```
Bash
Write
Agent
```

### 限定匹配器 {#specifier-matcher}

**仅当**工具的主要参数匹配 glob 模式时匹配该工具：

```
Bash(cargo test *)
Bash(npm run *)
Agent(explore)
Read(src/**)
Edit(src/**)
```

只有具有已知主要参数的工具才支持限定匹配器；任何其他工具只能按名称匹配。

| 工具 | 主要参数 |
|---|---|
| `Bash` | `command` |
| `Agent` | `subagent_type` |
| `Read` | `file_path` (或 `path`) |
| `Edit` | `file_path` |

### Glob 语法 {#glob-syntax}

| 模式 | 匹配项 |
|---|---|
| `cargo test *` | `cargo test --all`, `cargo test my_mod` |
| `npm run *` | `npm run build`, `npm run test` |
| `safe-cmd:*` | `safe-cmd:foo`, `safe-cmd:bar` |
| `exp*` | `explore`, `experiment` |

:::note
Glob `safe-cmd:*` **不**匹配 `safe-cmd --flag`。使用 `safe-cmd *`（带空格）以匹配用空格分隔的参数。
:::

:::warning
单命令通配符**不**保证多阶段命令。`Bash(npm run *)` 匹配 `npm run build`，但**不**匹配 `npm run build && rm -rf /` 或 `npm run build | sh` — `&&` / `||` / `;` / pipe 序列的每个阶段都必须单独匹配规则，因此被允许的前缀不能让未经批准的阶段蒙混过关。
:::

格式错误的权限规则会被逐个跳过并发出警告。有效的同级规则和其他设置仍会加载。

## 工具过滤 {#tool-filtering}

```bash
# 仅允许这些工具（白名单）
ante --include-tools Read Glob Grep "analyze the code"

# 移除这些工具（黑名单）
ante --exclude-tools Bash Write "read-only analysis"

# 细粒度：仅针对特定命令允许 Bash
ante --include-tools Read "Bash(cargo test *)" "Bash(cargo clippy *)" "analyze and test"
```

:::tip
工具过滤和权限是独立的。过滤控制会话中**存在**哪些工具；权限控制现有的工具是否**需要批准**。
:::

## 特定模式行为 {#mode-specific-behavior}

在 **TUI 模式**下，需要批准的工具会显示交互式提示。您可以批准或拒绝每次调用、在会话的剩余时间内授权，或者保存一条“始终允许”的规则（参见 [会话授权](#session-grants)）。

在**无头模式**下，隐含 `yolo` 模式。使用 `--include-tools` 或 `--exclude-tools` 来限制智能体能做什么。
