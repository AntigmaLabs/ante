## 设置文件 {#settings-file}

Ante 将用户偏好存储在 `~/.ante/settings.json` 中：

```json
{
  "model": "claude-sonnet-4-6",
  "provider": "anthropic",
  "theme": "default",
  "permission_mode": "auto",
  "permissions": {
    "allow": ["Bash(npm run *)"],
    "deny": ["Bash(rm *)"]
  },
  "has_completed_onboarding": true,
  "ambient_prompt_suggestion": true,
  "ambient_thinking_phrase": true,
  "channel": "stable",
  "resize_reflow": "conservative",
  "status_line": ["model-name", "current-dir"],
  "status_line_command": {
    "command": "~/.config/ante/statusline.sh",
    "padding": 1,
    "refresh_interval": 5
  },
  "model_thinking": {
    "claude-sonnet-4-6": "Enabled",
    "gpt-5.4": "Deep"
  },
  "mcp_servers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  }
}
```

| 字段 | 描述 |
|---|---|
| `model` | 默认模型名称 |
| `provider` | 默认 API 提供商 |
| `theme` | TUI 颜色主题 |
| `permission_mode` | 默认权限模式（`strict`、`auto` 或 `yolo`）。无法识别的值将被忽略，而不会导致整个文件解析失败 |
| `permissions` | 持久化工具权限规则，按 `allow`（允许）、`ask`（询问）和 `deny`（拒绝）匹配器分组（参见 [权限](/configuration/permission)） |
| `has_completed_onboarding` | 是否已完成引导流程 |
| `ambient_prompt_suggestion` | TUI 是否在回合结束后以幽灵文本的形式显示[下一个提示词建议](/usage/tui#next-prompt-suggestion)。除非设置为 `false`，否则默认开启 |
| `ambient_thinking_phrase` | TUI 是否在您输入时预测[针对特定任务的加载短语](/usage/tui#spinner-thinking-phrase)。除非设置为 `false`，否则默认开启 |
| `channel` | `ante update` 跟踪的发布渠道（`stable` 或 `nightly`）。默认值为 `stable`；旧版本的 `latest` 值会被视为 `stable`。参见 [更新与渠道](/start/update)。 |
| `resize_reflow` | 终端调整大小时的回滚策略：`conservative`（默认）或 `purge`（见下文） |
| `status_line` | 要显示在 TUI 状态栏底部的项目（见下文） |
| `status_line_command` | 渲染完全自定义状态栏的 shell 命令（见下文）。当设置时，其优先级高于 `status_line` |
| `model_thinking` | 针对特定模型的思考级别覆盖 — 键为模型名称，值为 `Disabled` / `Enabled` / `Deep` / `Max` |
| `mcp_servers` | 会话开始时要启动的 MCP 服务器（参见 [MCP 服务器](/extend/mcp)） |

### 状态栏 {#status-line}

`status_line` 字段控制在 TUI 底部栏显示哪些项目。它接受一个项目标识符的数组：

| 项目 | 描述 |
|---|---|
| `model-name` | 当前模型名称 |
| `provider` | 当前提供商 |
| `current-dir` | 当前工作目录 |
| `git-branch` | 当前 Git 分支（不可用时省略） |
| `thinking-level` | 当前思考级别（禁用时省略） |
| `pr-link` | 当前分支的 GitHub 拉取请求链接（需要 `gh` 命令） |
| `context-used` | 上下文窗口使用情况，显示为窗口剩余 `N% ctx`（直到已知前省略） |

默认值：`["model-name", "current-dir"]`。可通过 `~/.ante/settings.json` 或 TUI 中的 `/statusline` 命令进行配置。

### 基于命令的状态栏 {#command-based-status-line}

为了获得完全的控制，`status_line_command` 运行您选择的 shell 命令并将其输出渲染为状态栏，从而替换基于项目的状态栏：

```json
{
  "status_line_command": {
    "command": "~/.config/ante/statusline.sh",
    "padding": 1,
    "refresh_interval": 5
  }
}
```

可以将纯字符串作为简写：`"status_line_command": "echo hello"`。

| 字段 | 描述 |
|---|---|
| `command` | 脚本路径或内联 shell 命令，通过 `sh -c` 运行（必需） |
| `padding` | 额外的水平内边距列数（默认：`0`） |
| `refresh_interval` | 此外，每 N 秒重新运行一次（最小值为 1）。对时钟或外部数据很有用。省略则仅在会话事件时运行 |

**工作原理。** Ante 会将包含会话快照的 JSON 数据通过管道传给你的命令的 stdin，并显示该命令输出到 stdout 的内容。该命令在助手的每条消息后以及当模型、提供商、思考模式、Pull Request、工作目录或终端大小发生变化时重新运行（300ms 防抖）。运行时间上限为 5 秒，较新的运行会取消正在执行的运行。

JSON 输入是 [Claude Code 状态栏输入](https://code.claude.com/docs/en/statusline)的兼容子集，因此现有的 Claude Code 状态栏脚本可以原样使用：

```json
{
  "cwd": "/work/repo",
  "session_id": "ses_...",
  "version": "0.1.0",
  "model": { "id": "claude-sonnet-4-6", "display_name": "claude-sonnet-4-6" },
  "workspace": { "current_dir": "/work/repo", "project_dir": "/work/repo" },
  "thinking": { "enabled": true },
  "pr": { "number": 7, "url": "https://github.com/..." },
  "provider": "anthropic",
  "context_window": {
    "context_window_size": 200000,
    "total_input_tokens": 36000,
    "used_percentage": 18,
    "remaining_percentage": 82
  }
}
```

仅当检测到当前分支存在开放的拉取请求时才存在 `pr` 字段；在模型上下文限制已知的第一次响应后，`context_window` 字段会存在，并使用 Claude Code 的字段名报告原始窗口大小以及已使用/剩余百分比。`provider` 是 Ante 的扩展。该命令还在其环境变量中接收 `COLUMNS` 和 `LINES`（当前终端大小）以及 `ANTE_PROJECT_DIR`（包含 `.git` 的最近祖先目录）。

**输出。** stdout 的每一行都会成为底部状态栏的一行（最多 8 行）。ANSI 颜色和 OSC 8 超链接将被渲染；颜色状态会跨行保持。空白行将被丢弃，空输出则会渲染一个空白的状态栏。

一个最小化的示例脚本：

```bash
#!/bin/sh
input=$(cat)
model=$(echo "$input" | jq -r '.model.display_name')
dir=$(basename "$(echo "$input" | jq -r '.workspace.current_dir')")
printf '\033[36m[%s]\033[0m %s' "$model" "$dir"
```

在将其指向 `command` 之前，请使其成为可执行文件（`chmod +x`）。如果命令执行失败 — 不可执行、非零退出码或超时 — 状态栏底部将根据脚本的 stderr 显示一行的诊断信息，例如 `status line: sh: …: Permission denied`。脚本的更改将在下一次运行时被拾取，但是对 `settings.json` 本身的更改需要重启才能生效。

### 调整大小重排 {#resize-reflow}

当调整终端窗口大小时，ante 会以新的尺寸重建其显示。`resize_reflow` 字段选择对位于可见屏幕上方的回滚历史记录执行什么操作：

| 值 | 行为 |
|---|---|
| `conservative`（默认） | 从不重写已打印的回滚记录。在每个终端上都安全；在大幅度拖拽调整大小后，靠近调整点的少数几行可能会保持其旧的换行。 |
| `purge` | 清除终端的回滚记录并在新宽度下重放最近的对话记录 — 在调整大小后，会话看起来就好像一开始就是在这个最终尺寸下开始的一样。 |

```json
{ "resize_reflow": "purge" }
```

`purge` 选项是需要手动开启的，而不是自动执行的，因为它需要终端支持擦除回滚转义序列（`CSI 3 J`，即 terminfo 中的 `E3` 功能）— 而 ante 无法检测到该支持：被忽略的 `3 J` 会默默失败，并且在这样的终端上启用 `purge` 反而会复制回滚记录。大多数终端都支持它，但 iTerm2 有一个高级设置 — "Prevent CSI 3 J from clearing scrollback history"（防止 CSI 3 J 清除回滚历史记录） — 它会阻止此操作。要检查您的终端，请运行：

```bash
seq 1 200; printf '\033[2J\033[3J\033[H'
```

然后向上滚动 — 如果数字消失了，说明您的终端支持 `3 J`，您可以安全地启用 `purge`。

在 iTerm2 中，可以在 **Settings → Advanced**（设置 → 高级）下切换此功能：搜索 "3 J" 并将 **"Prevent CSI 3 J from clearing scrollback history"** 设置为 **No** 以允许（`purge` 所需），或设置为 **Yes** 以阻止。更改立即生效 — 重新运行上面的检查以确认。

`purge` 的权衡：第一次调整大小会清除该选项卡回滚记录中的所有内容，包括在 ante 启动之前的 shell 输出，并且只有最近的 2,000 行会话记录会在调整大小时重新播放。在 tmux 或 zellij 中，无论此设置如何，ante 始终使用 purge 策略，因为它们都可靠地支持 `3 J`。

可以通过 CLI 标志在每个会话中覆盖设置。

| `OPENAI_COMPATIBLE_API_KEY` | OpenAI 兼容提供商的 API 密钥 |

| `ZAI_API_KEY` | Zai 的 API 密钥 |
| `DEEPSEEK_API_KEY` | DeepSeek 的 API 密钥 |
| `ALI_CODING_PLAN_API_KEY` | 阿里代码计划的 API 密钥 |
| `ANTIX_API_KEY` | Antix 的 API 密钥 |
| `MODEL_BASE_URL` | 全局后备基础 URL（可被下面特定提供商的变量覆盖） |
| `ANTHROPIC_BASE_URL` | 覆盖 Anthropic 基础 URL |
| `OPENAI_BASE_URL` | 覆盖 OpenAI 基础 URL |

| `MODEL_MAX_TOKENS` | 覆盖最大输出 token 数量（整数） |
| `MODEL_CONTEXT_LIMIT` | 覆盖最大上下文窗口大小（整数） |
| `ANTE_LOCAL_PROVIDER_PORT` | 覆盖本地提供商端口（默认：8080） |
| `ANTE_HOME` | 覆盖主配置目录（默认：`~/.ante`） |
| `ANTE_INSTALL_DIR` | 仅限安装程序的二进制安装目录覆盖（默认：`~/.ante/bin`） |
| `ANTE_OPENAI_TRANSPORT` | OpenAI 响应传输：`http_sse`（默认）或 `websocket_auto`（参见 [OpenAI 传输](/reference/catalog-reference#openai-transports)） |

## 目录结构 {#directory-structure}

### 用户级别 (`~/.ante/`) {#user-level-ante}

```
~/.ante/
├── settings.json      # 用户偏好设置
├── catalog.json       # 自定义提供商/模型目录
├── AGENTS.md          # 全局指令
├── sessions/          # 持久化会话（用于 /resume）
├── skills/            # 用户级别的技能
└── agents/            # 用户级别的子智能体
```

### 项目级别 {#project-level}

```
AGENTS.md              # 项目指令

.ante/
├── skills/            # 特定于项目的技能
└── agents/            # 特定于项目的子智能体

.agents/
├── skills/            # 特定于项目的技能
└── agents/            # 特定于项目的子智能体

.claude/
├── skills/            # 特定于项目的技能（Claude Code 兼容性）
└── agents/            # 特定于项目的子智能体（Claude Code 兼容性）
```

### 项目记忆 (`~/.ante/projects/`) {#project-memory-anteprojects}

项目作用域的状态 — 记忆、持久化会话、事件日志 — 位于 `~/.ante/projects/<project-id>/` 下，其中 `<project-id>` 是项目绝对路径的经过清理的形式。

```
~/.ante/projects/
└── <project-id>/
    └── memory/
        └── MEMORY.md      # 该项目的自动记忆
```

### 临时文件 {#temporary-files}

按项目划分的临时文件位于 `~/.ante/cache/<project-id>/` 下。

## 优先级 {#precedence}

配置按此顺序解析（后面的会覆盖前面的）：

1. 内置默认值
2. `~/.ante/settings.json`
3. CLI 标志（`--model`，`--provider` 等）
