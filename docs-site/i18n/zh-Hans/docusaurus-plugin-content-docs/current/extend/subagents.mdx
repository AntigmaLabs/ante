---
title: "子智能体"
description: "将复杂任务委托给专业的子智能体"
---

子智能体是专业的智能体，主智能体可以派生（spawn）它们来处理复杂的多步骤任务。每个子智能体都在拥有自己独立的提示词、工具集和可选模型覆盖的环境下运行。

## 内置子智能体 {#built-in-sub-agents}

Ante 附带三个内置的子智能体：

### general {#general}

一个通用的智能体，用于研究复杂问题、搜索代码以及执行多步骤任务。当主智能体需要执行它没有把握在几次尝试内完成的搜索时，就会委托给这个智能体。

### explorer {#explorer}

一个专门用于快速探索代码库的智能体。它可以通过模式快速查找文件、搜索代码中的关键字，并回答关于代码库结构的问题。

### ante-guide {#ante-guide}

一个针对有关 Ante 自身问题（如功能、配置、协议、技能和子智能体）的助手。主智能体会将用户关于 Ante 自身功能的问题路由到此处。

## 创建自定义子智能体 {#creating-custom-sub-agents}

在 `~/.ante/agents/`（用户级别）或下面任意项目级别的位置创建一个带有 YAML 前言的 Markdown 文件：

```markdown
---
name: security-reviewer
description: 审查代码是否存在安全漏洞以及 OWASP Top 10 问题
tools:
  - Read
  - Grep
  - Glob
---

您是一位专注于安全的代码审查员。分析提供的代码以找出：

- 注入漏洞（SQL、命令、XSS）
- 认证和授权缺陷
- 敏感数据泄露
- 安全配置错误
- 已知的易受攻击的依赖项

提供包含严重性评级和补救步骤的调查结果。
```

### 前言字段 {#frontmatter-fields}

| 字段 | 是否必需 | 描述 |
|---|---|---|
| `name` | 是 | 智能体的唯一标识符 |
| `description` | 是 | 该智能体的作用（展示给主智能体，以供其做委托决策） |
| `model` | 否 | 覆盖此智能体的 LLM 模型 |
| `tools` | 否 | 限制此智能体可以使用哪些工具 |

## 子智能体如何工作 {#how-sub-agents-work}

当主智能体遇到与子智能体描述相匹配的任务时，它会使用 `Agent` 工具派生该子智能体：

1. 主智能体评估可用的子智能体及其描述
2. 它通过 `Agent` 工具，附带详细的提示词委托任务
3. 子智能体带着自己的上下文独立运行
4. 结果返回给主智能体，主智能体将其整合到当前对话中

```
┌────────────┐     Agent     ┌──────────────┐
│ 主智能体   │ ────────────▶ │   子智能体   │
│            │ ◀──────────── │  (Explorer)  │
│            │    结果       └──────────────┘
│            │
│            │     Agent     ┌──────────────┐
│            │ ────────────▶ │   子智能体   │
│            │ ◀──────────── │  (General)   │
└────────────┘    结果       └──────────────┘
```

## 发现机制 {#discovery}

子智能体的发现按优先级顺序进行（后面的智能体根据名称覆盖前面的智能体）：

1. 内置智能体（`general`、`explorer`、`ante-guide`）
2. `~/.ante/agents/`（用户级别）
3. `.agents/agents/`（项目级别）
4. `.ante/agents/`（项目级别）
5. `.claude/agents/`（项目级别，Claude Code 兼容性）

用户级别和项目级别的智能体与内置的智能体一起加载。所有可用的智能体都在会话初始化时被注册，并通过 `ExtensionRefreshed` 协议事件进行刷新。
