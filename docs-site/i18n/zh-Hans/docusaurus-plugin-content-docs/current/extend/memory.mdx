Ante 拥有一个持久化记忆系统，让智能体能够在跨对话中积累知识。见解、模式和学到的教训会被存储在记忆文件中，并在未来的会话中自动加载到系统提示词中。

## 工作原理 {#how-it-works}

每个项目都有一个位于 `~/.ante/projects/<project-id>/memory/` 的记忆目录，其中 `<project-id>` 是项目绝对路径的清理形式。关键文件是 `MEMORY.md` — 它的内容在每次对话开始时被注入到系统提示词中。

在交互式 TUI 中，自动记忆默认处于启用状态；在无头 `-p` 运行中，自动记忆默认处于禁用状态。使用 `--enable-auto-memory` 为无头运行启用记忆功能，或使用 `--disable-auto-memory` 为 TUI 会话关闭该功能。

### 自动行为 {#automatic-behavior}

随着智能体在您的项目中工作，它会：

1. **查阅**现有的记忆文件，以建立在以往经验的基础上
2. **记录**当它遇到常见错误或有用模式时产生的新见解
3. **更新**或移除被证明是错误或过时的记忆

### MEMORY.md {#memorymd}

这是主要的记忆文件。它会被注入到系统提示词中，上限为 200 行或 25 KB，以先到者为准（当超出限制时会附加一条截断说明）。保持其简洁 — 如果需要详细信息，请链接到单独的主题文件。

```markdown
# 项目模式

- 对于所有可能失败的函数，使用 `anyhow::Result`
- 测试放在代码旁边的 `#[cfg(test)]` 模块中
- 常见问题请参阅 [debugging.md](debugging.md)

# 已知问题

- auth 模块需要重构（在 #123 中跟踪）
```

### 主题文件 {#topic-files}

对于详细的笔记，创建单独的文件并从 `MEMORY.md` 中引用它们：

```
memory/
├── MEMORY.md           # 主文件（自动加载，最多 200 行）
├── debugging.md        # 详细的调试笔记
├── patterns.md         # 代码模式和约定
└── architecture.md     # 架构决策
```

## 记忆类型 {#memory-types}

开启自动记忆时，系统会教导智能体保存**类型化**的记忆 — 每个主题文件都带有 `name`、`description` 和 `type` 的前言元数据，以便未来的会话能够判断什么是相关的。共有四种类型：

| 类型 | 记录的内容 |
|---|---|
| `user` | 用户的角色、专业知识、目标和偏好 — 以便针对他们量身定制解释和默认设置。 |
| `feedback` | 从纠正和确认中提取出的关于如何在此项目中工作的指导。以规则开头，随后是 **Why（原因）** 和 **How to apply（如何应用）** 行。 |
| `project` | 无法从代码或 git 中推导出的正在进行的工作、决策或约束。采用相同的 **Why** / **How to apply** 结构；相对日期被存储为绝对日期。 |
| `reference` | 指向当前事实来源所在的外部系统（如 Linear 项目、Grafana 面板、Slack 频道）的指针。 |

一个类型化的主题文件如下所示：

```markdown
---
name: bundle-refactors
description: 在此区域进行重构时，首选一个合并的 PR
type: feedback
---

对于涉及此区域的多文件重构，更倾向于使用单个合并的 PR，而不是将其拆分。

**Why:** 用户确认了这一点 — 这是一个经验证的决策，而不是一种纠正。
**How to apply:** 触及此区域的多文件重构。
```

智能体会刻意**不**保存密钥、进行中的任务状态，或是任何已经可以通过重新阅读代码库获得的信息（代码结构、文件路径、约定 — 这些应该放在 `AGENTS.md` 中）。回忆起来的记忆被视为反映过去某个时刻的背景上下文，因此智能体在采取行动之前，会重新验证记忆中提到的任何文件、标志或函数。

## 指南 {#guidelines}

记忆系统遵循以下原则：

- **简洁** — `MEMORY.md` 在 200 行后会被截断，因此请保持专注
- **语义化** — 按主题组织，而不是按时间顺序
- **准确** — 更新或移除过时的信息
- **可操作** — 记录什么有效，什么无效，以及原因

## 记忆是按项目划分的 {#memory-is-per-project}

记忆的作用域限定在每个项目目录下。不同的项目具有独立的记忆目录。这意味着智能体积累的关于您的 React 前端知识不会干扰它关于您的 Rust 后端的知识。

## 手动编辑 {#manual-editing}

您可以直接编辑记忆文件 — 它们是纯 Markdown 文件。在会话期间，智能体也可以使用 `Write` 和 `Edit` 工具更新它们。
